# 图灵小程序配网绑定 — 可行性核查

> 结论先行：**当前设备不能用图灵小程序配网绑定。** 三重前提（平台、协议、入口）全部不满足，
> 且即使全部打通，**绑定的是图灵 IoT 平台账号，与我们的单词卡云端（nglearn）不相干**——
> 配完网也拉不到卡。实测证据见 §2。

---

## 1 两套体系对照

| 维度 | 我们的链路 | 图灵小程序链路 |
|---|---|---|
| 云端 | `nglearn.turingapi.com`（图灵 AI 拍学机） | `iot-ai.turingapi.com`（TuringOS IoT） |
| 凭据 | apikey `2cad742e…` + deviceId `c8586a630000`（MAC 风格） | apiKey + deviceId `vkkv00c00000xxxxx`（平台分配号段） |
| 设备注册 | 整批烧录，无需在平台注册 | **必须**在 AI 开放平台登记，由平台发 deviceId |
| BLE 服务 | `FEE1` 主服务，自定义 `0x8D`/`0x8A` 指令帧 | `0xFFFF` 服务，`0xFF01` 写 / `0xFF02` 通知 |
| BLE 帧 | 联盛德 V1.2：TLV + AES-ECB 分片（固定 14 字节） | `A0` 分片帧 + `B0` 信息帧，payload 为 urlencode 后 hex |
| 绑定 | apikey + deviceId 本地绑定（`0x8A` 判据） | openId（微信）绑定，`/open/device/bind-wechat-user` |
| 客户端 | 自研 App | 微信小程序 + 公众号菜单 OAuth |

**核心结论**：这不是"换个协议"能解决的，是**另一条产品线**。小程序配网成功只意味着
「设备连上了 WiFi 且绑到了某个微信公众号」，不会让我们的 App 拉到一张单词卡。

---

## 2 实测证据（2026-10-26）

### 2.1 绑定接口 1：`POST /open/device/bind-wechat-user`

| 请求 | 响应 |
|---|---|
| 我们的 `apikey=2cad742e…` + `deviceId=c8586a630000` + 真实形态 openId | `200 {"status":200,"body":[]}` |
| **随机假 apikey** + 同一 openId | `200 {"status":200,"body":[]}`（**逐字节相同**） |
| 我们的 apikey，**缺 openId** | `200 {"status":200,"body":[]}` |
| 空数组 `[]` | `400 {"status":400,"body":[]}` |

判读：
1. **不校验 apiKey**——假 key 与真 key 返回一模一样，说明服务端没走到 apiKey 校验分支。
2. **`body: []` 不是成功**，文档里成功会回带 `openId/apiKey/deviceId` 的对象。
3. 我们的设备 `c8586a630000` **不在该平台**（查不到才回空数组，且不报错）。

### 2.2 绑定接口 2：`POST /iot/bind_from_sinvoice`

| 请求 | 响应 |
|---|---|
| 我们的 apikey + 短 openId | `41007 openId错误或未绑定` |
| **随机假 apikey** + 短 openId | `41007`（**相同**） |
| 文档示例 apikey + 示例 deviceId | `41007`（**相同**） |
| 我们的 apikey + 空 openId | `41007`（**相同**） |

判读：该接口在 openId 校验失败时**提前返回**，压根没走到 apiKey 校验。
所以 **`41007` 不能用来推断「apikey 有效」**——之前若有结论基于此，需要推翻。

> ✅ 两个接口都不能作为「设备是否已注册」的判据。要确认注册状态，只能让图灵 IoT 侧查库。

## 3 三重前提逐项判断

| # | 前提 | 状态 | 说明 |
|---|---|---|---|
| 1 | 设备在 `iot-ai` 平台注册（拿到 `vkkv…` 号段 deviceId） | 🔴 不满足 | 实测查不到；我们整批是 `nglearn` 的 apikey，两套不互通 |
| 2 | 固件实现图灵小程序 BLE 协议（`FFFF` + `A0`/`B0`） | 🔴 不满足 | 与 W800 现有 V1.2 帧格式零重叠，等于重写一套配网。**估 3~4 人天** |
| 3 | 公众号菜单入口（appid + apikey + 图灵开通） | 🔴 不满足 | 入口是 OAuth 跳转 `iot-ai.turingapi.com/mini-program/find-open-id/{APIKEY}`；官方文档明写「**需要联系图灵相关人员开通此功能才可使用**」 |

补充：小程序三种联网方式里，**声波**的编码器是服务端内嵌闭源 ELF（按 apiKey 分 vendor），
设备端只能等图灵给 SDK；**二维码**要出码端配合；**蓝牙**是三者中唯一能自研的，
但需要按小程序源码破译的帧格式实现（参考 `docs/dl/esp32-netbind-demo_src.zip`，
里面有完整的 C 实现与破译说明）。

## 4 建议

### 4.1 现在就能配网，不需要小程序

v2.11.1 已具备完整配网能力，且 **v2.11.1 补了手输兜底**：

| 固件状态 | 配网方式 |
|---|---|
| 已实现 V1.2（`0x88`/`0x89`） | 设备扫 → 列表点选（体验最好） |
| 仍是 V1.0 基线 | 6s 后自动亮出「手动输入 WiFi」，照常配网 |

两条路都不依赖图灵小程序，也不依赖小程序资质。

### 4.2 如果确实需要「小程序」形态

**可以自研，不必走图灵那套**。做法与我们 App 完全一致，只是把客户端换成微信小程序：

- 用 `wx.startBluetoothDevicesDiscovery` 按 `AIPicCamera` 名字或 ORG-ID 过滤
- 用 `wx.createBLEConnection` + 特征值读写，帧格式**沿用 W800 V1.2**（不碰 `FFFF` 协议）
- 拿到列表 → 让用户点选 → 用同一套 `0x0A` 指令下发 SSID/密码
- 绑定仍走我们的 apikey + deviceId，**不需要 openId、不需要图灵 IoT 平台**

成本估：3~5 人天（小程序端）+ 小程序主体资质与类目备案（走公司主体，时间不可控）。

⚠️ 一个绕不开的限制：iOS 上小程序**不能**替设备连 WiFi（`wx.connectWifi` 仅 Android），
但我们走的是「BLE 下发 → 设备自己连」，**iOS 也能用**，这点比 `connectWifi` 方案更稳。

### 4.3 不建议

让我们的设备去接 `iot-ai` 平台换取小程序能力。理由：

1. 要重新在平台注册设备、换 deviceId 号段 → 存量 66 条记录全部失联
2. 绑定关系变成微信 openId → 引入账号体系与隐私合规（儿童设备尤其敏感）
3. 配完网仍然拉不到卡（数据在 nglearn，不在 iot-ai）
