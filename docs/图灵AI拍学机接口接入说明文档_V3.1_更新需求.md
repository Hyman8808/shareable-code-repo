🔴 **新增说明（请附在本节末尾）**：

> **关于设定语言**
>
> 设备的"设定语言"（识别结果按哪种语言返回、用哪种语言合成音频）由 App 端设置并写入云端，云端按 `deviceId` 匹配。
> **设备无需在请求中携带任何语言参数，也无需感知语言被修改这件事**——App 改完语言后，设备**下一次请求**拿到的即为新语言的结果与音频。
> 语言只影响 2.3 中新增的 `name_localized` / `name_localized_lang` / `tts_url_localized` 三个字段；`name_chinese`、`name_english`、`tts_url`、`tts_url_english` 的含义与取值**保持不变**。

### 2.3 返回数据示例及参数说明 🔴 新增字段

#### 🔴 新增 3 个返回字段（均为 `data` 层，与 `name_english` 同级）

| 字段 | 必须 | 类型 | 说明 |
|---|---|---|---|
| `name_localized` | N | String | **设定语言的物品名称**。语言由 App 设置、云端按 `deviceId` 匹配，设备无需传参。设定语言为中文时与 `name_chinese` 相同 |
| `name_localized_lang` | N | String | **`name_localized` 实际使用的语言代码**（见下方语言取值表）。⚠️ 必须回显"实际返回的语言"，不是"请求的语言"——云端发生回落时，设备据此判断该按什么语言显示、选哪套字体 |
| `tts_url_localized` | N | Array | **设定语言的物品音频地址**，结构与 `tts_url` 一致（字符串数组） |

🟡 **`name_chinese` 说明补充一句**（字段本身、类型、必填性都不变）：

> `name_chinese`：物品的中文名称。**保留该字段以兼容存量设备**；设定语言为简体中文时与 `name_localized` 取值相同。

#### 🔴 修订后的返回示例（在原文 result-2「最终数据结果」上新增 3 行，其余字节不变）

        "name_english": "Bus",

> 注：`information.pinyin` 在非中文语言下返回空串（原字段不变，只约定取值）；`information.description` 建议按设定语言返回，不强制。

#### 🔴 语言取值表（新增，本期支持 9 项）

| 代码 | 语言 | 代码 | 语言 |
|---|---|---|---|
| `zh` | 简体中文 | `fr` | 法语 |
| `zh-Hant` | 繁体中文 | `de` | 德语 |
| `en` | 英语 | `es` | 西班牙语 |
| `ja` | 日语 | `ru` | 俄语 |
| `ko` | 韩语 | | |

🔴 **繁体必须单独实现，不能用简繁转换代替**：

> `zh-Hant` 与 `zh` 不只是字形不同——用词和读音也有差异（"裡/里"、"後/后"、"著/着"），**TTS 必须单独合成繁体音频**。
> 若用"简体文本 + 简繁字符映射"糊出来，会出现"字形对了、读音和用词不对"的假繁体，儿童学习场景不可接受。

#### 🔴 回落规则（写进 2.3 末尾，**不新增状态码**）

| 情况 | 返回 | `name_localized_lang` |
|---|---|---|
| 设备尚未设置语言 | 按简体中文返回 | `zh` |
| 设置的语言本期不支持 | 回退简体中文 | `zh` |
| 正常 | 按设定语言返回 | 该语言代码 |

> 三种情况 `code` 均为 `200`。设备端判据：`name_localized_lang` 与自己显示的语言不一致 → 说明云端回落了，界面按 `name_localized_lang` 显示，不报错。

#### ⬜ 其余返回字段不变

`code` / `data` / `done` / `globalId` / `message` / `clientRequestId` 的结构与说明**全部不变**；
`data` 层 `explore` / `learning` / `information` 三块的结构与说明**全部不变**；
`information` 内 `pinyin` / `name_english` / `phonetic` / `description` 的类型与必填性**全部不变**。
