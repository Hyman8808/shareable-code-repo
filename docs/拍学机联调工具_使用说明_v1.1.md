# 拍学机联调工具 · 使用说明 v1.1

> 用途：给**客户对接人与固件工程师**做设备联调用的独立 App。
> 与产品版 App 完全隔离，可同时安装。
> 2026-10-26 · 对应 App 代码 v2.11.2 / 协议 V1.2

## v1.1 改了什么（相对 v1.0）

| # | 改动 | 为什么 |
|---|---|---|
| 1 | 「手输 SSID」弹窗**自动填入手机当前连着的 WiFi 名称**，可改 | 让客户不用手打网络名。SSID 里有中文/空格/大小写，打错一个字最后会表现成「密码错误」，极难自查 |
| 2 | 手机连的是 **5G** 时，弹窗顶部显式警告并给出频率 | 相机只支持 2.4G。预填一个 5G 专用名称等于把一个**必然失败**的值放在最显眼的位置，用户点发送、等 50 秒、最后拿到误导性结论 |
| 3 | 配网页一进来就在「报文」页记一条 `本机 WiFi：名称（频率，2.4G/5G）` | 读不到默认值时，要能一眼分清是「没授权」「没连网」还是「系统不给」，否则排障会绕远路 |
| 4 | 未读到当前 WiFi 时**行为完全不变**：输入框留空，由用户自己填 | 权限被拒、没连 WiFi、系统返回 `<unknown ssid>` 都是常态，不能因此把配网入口堵住 |

## 1. 为什么单独做一个工具包

产品版 App（「单词卡相机」）不适合直接给客户联调用，三个原因：

| 问题 | 具体表现 |
|---|---|
| 看不到协议细节 | 产品版把 BLE 收发的每一帧都藏起来了，固件出问题时无从判断是「没发出去」还是「设备没回」 |
| 带产品逻辑干扰 | 收藏、AI 美化、额度、多设备隔离，客户会以为是联调必须的步骤 |
| 凭据写死 | 产品版 apikey 在构建期注入，客户设备烧的是自己的 apikey，改不了就拉不到记录 |

联调工具把这三件事反过来做：**全程显示每一帧**、**只有配网和记录**、**apikey 可手填**。

## 3. 三个页签怎么用

### 3.1 配网

按顺序走，每一步都写在状态栏上：

| 步骤 | 界面表现 | 对应协议 |
|---|---|---|
| ① 点「扫描设备」 | 列出附近设备，标题是广播名或 MAC 后 6 位 | 广播包 |
| ② 每行的副标题 | `MAC · 广播版本 0x12 · 是否支持 V1.2 列表` | 广播里的 Version 字段 |
| ③ 点一行 | 状态变「连接中 → 已连接 → 服务发现 → 密钥协商」 | `0x0F`/`0x8F` |
| ④ 自动读设备信息 | 显示 apikey / deviceId / 固件版本 / ORG-ID / 型号 | `0x0D`/`0x8D` |
| ⑤ 自动请求扫描 | 「让设备扫描 2.4G 热点…」 | `0x0E`/`0x8E` |
| ⑥ 出现热点列表 | 点一行 → 输密码 → 「下发配网」 | `0x0A`/`0x8A` |
| ⑦ 结果 | 成功显示 IP 与 MAC；失败显示 errorId 与含义 | `0x8A{0x81}` |

**「手输 SSID」按钮**：固件还没实现「设备扫 WiFi 回列表」时用这个直接下发，不然配不了网。**固件早期必须用这条路。**

v1.1 起，点它会**自动填入手机当前连着的 WiFi 名称**，客户只需确认或改一下，不用手打：

| 情况 | 弹窗表现 |
|---|---|
| 读到且是 2.4G | 输入框预填名称，光标直接落在密码框 |
| 读到但是 5G | 预填，并在顶部红字警告「相机只支持 2.4G，若是 5G 专用名称请改掉」，同时给出频率 |
| 读不到（未授权 / 没连网） | 输入框留空，提示「请手动填写」，**与 v1.0 行为一致** |

> 第一次点会弹一次权限申请（Android 13+ 是「附近的设备」，更早是「位置信息」）。
> **拒绝也没关系**，只是没有默认值，照样能手输配网。
> 系统「定位开关」关着时读不到 SSID，这是 Android 10 以上的限制，不是 App 的问题。

**设备信息区的三个值要重点看**：

- `apikey` 为「未返回」→ 固件没实现 `0x8D` 的 `0x0A` TLV，或者根本没烧凭据
- `deviceId` 与设备贴纸上的一致 → 云端能按它查到记录
- `固件版本` 与预期不符 → 烧错包了

### 3.2 报文

BLE 收发的每一帧都在这里，格式 `时间 方向 十六进制`：

- `TX` = 手机发给设备
- `RX` = 设备发给手机（日志里显示为空方向或设备侧标记）
- 非帧的行是流程节点（「密钥协商完成」「扫描结果为空」等）

**右上三个按钮**：复制（整份日志到剪贴板，可直接发微信）、清空。

**判据示例**：

| 现象 | 说明 |
|---|---|
| 只有 TX 没有 RX | 设备没回，八成是命令码不认或分片没组完 |
| TX 帧长度是 5 的倍数且很短 | 空 PAYLOAD 帧没放零长占位 TLV，指令根本没发出去 |
| 出现 `0x8E` 但无 `0x88` | 设备回了 ACK 但没推列表，扫描功能没实现 |

### 3.3 记录

三个输入框：`apikey` / `deviceId` / `lang`，加一个云端地址（默认 `https://nglearn.turingapi.com/`）。

点「拉取记录」→ 显示最近 20 条，每行格式：

```
物品名（设定语言优先，其次中文）
EN 英文名   zh 中文名   localized=本地化名(语言码)   id=记录ID
```

**点任意一行可以看这条记录的完整原始 JSON**，核对字段用这个。

> `localized=` 这一段只在云端返回了 `name_localized` 时才出现。
> 如果填了 `lang=ko` 还是只有 `zh`，说明云端没实现 V3.1 的多语言字段。

## 4. 本次实测结论（2026-10-26，演示机 c8586a630000）

用这个工具对现有样机跑了一遍，得到三条事实，都已写进协议与联调清单：

| # | 结论 | 证据 |
|---|---|---|
| 1 | ✅ **固件已实现 `0x8D` 的 5 个 TLV** | 读到 apikey=`2cad74…8519`、deviceId=`c8586a630000`、ORG-ID=`0x070C`、型号=1、固件=1.1 |
| 2 | ❌ **固件未实现 `0x0E` 热点列表推送** | 发出 `0x0E` 后只收到一帧 `0E 0F 80 01 71 3B BD`，15 秒内没有任何 `0x88`/`0x86` 行，最终超时 |
| 3 | ⚠️ **广播 Version 与固件版本不一致** | 广播 `Version=0x10`，但 `0x8D` 自报固件 `1.1 (0x11)` |
| 4 | ❌ **老云端忽略 `lang` 参数，不返回 `name_localized`** | 记录页填 `lang=ko` 与不填，返回内容完全一致，无韩文、无 localized 字段 |

**第 3 条要请固件改**：App 判断「是否支持 V1.2 列表」用的是广播里的 Version（`>= 0x12` 才算支持）。广播停在 `0x10` 会让 App 一直按老格式解析，即使固件其实支持新列表也会走错分支。**固件升级时必须同步改广播里的 Version 字段。**

**第 4 条要请云端补**：V3.1 文档定义的三个字段（`name_localized` / `name_localized_lang` / `tts_url_localized`）在 nglearn 上还没有实现。设备端按文档接了也拿不到值，会一直走回落分支（显示中文）。

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 不做绑定 | 只验证协议，不写设备列表、不写数据库。绑定的产品逻辑在产品版 App 里 |
| 不做断点续传 | 一次连接跑一轮流程，中途断电要重来 |
| 记录只拉 20 条 | 联调看字段够用；要看全量请用产品版 |
| 不显示 RSSI 历史曲线 | 只显示当前值 |
| 平板横屏时页签偏宽 | 纯样式问题，不影响功能 |

## 6. 出包命令

```bash
export JAVA_HOME="D:/devtools/jdk-17.0.20.1+1"
export ANDROID_HOME="D:/devtools/android-sdk"
cd android-app
gradle.bat --stop
gradle.bat clean            # 必须确认 app/build 消失
gradle.bat assembleDevtoolDebug --no-build-cache
```

产物：`app/build/outputs/apk/devtool/debug/app-devtool-debug.apk`

**与产品版共用同一套源码**，只是多了一个 `devtool` flavor：

| 位置 | 内容 |
|---|---|
| `app/build.gradle` | `productFlavors.devtool`（`applicationIdSuffix ".devtool"`） |
| `app/src/devtool/AndroidManifest.xml` | 移除产品主入口，只留 `DevToolActivity` |
| `app/src/devtool/java/.../devtool/` | 工具全部代码（6 个文件） |
| `app/src/devtool/res/` | 工具专用布局与资源，**文件名统一 `dev_` / `item_dev_` 前缀**，避免与产品版同名资源互相覆盖 |

> ⚠️ 踩过的坑：flavor 的资源会**覆盖** main 里的同名文件。一开始把布局命名成 `fragment_cards.xml`，直接覆盖了产品版的同名布局，产品代码全部编译失败。所以工具侧资源一律加前缀。
