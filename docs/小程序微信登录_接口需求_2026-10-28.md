# 小程序微信登录 · 接口需求（2026-10-28）

> 提出：王宏元 ｜ 目标读者：王秀文（#2835 云端）
> 关联：#2835（账号域）、#2826（App/iOS 开发）
> 客户端侧**已实现完毕**，本文只定义服务端要交付的接口形状。接口一通，客户端零改动即可登录。

---

## 0. 一句话

小程序加一条登录路：**微信登录**。前端只把 `wx.login` 拿到的 `code` 交出去，服务端换 `openid` 建号、发令牌。
不需要支付宝登录（微信小程序里没有这个 SDK，也不该有），不需要邮箱登录（首发），不需要 Apple / Google。

---

## 1. 为什么是微信登录，为什么不碰支付宝

| 项 | 判断 | 理由 |
|---|---|---|
| 微信登录 | **做** | 小程序只能跑在微信里，`wx.login` 是零输入、零短信成本。短信验证码 0.05 元/条 + 手输 6 位，在小程序里没有竞争力 |
| 支付宝登录 | **不做，也无法做** | 支付宝登录是**支付宝小程序**的 SDK。我们是微信小程序，没有这个入口。Android App 侧也收敛为「微信 + 手机号」 |
| 手机号验证码 | 小程序里降为**可选绑定** | 只用于换手机找回与跨端识别，不作为首登门槛 |
| Apple / Google | 不做 | 首发国内。🔴 注意耦合：**一旦 iOS App 接微信登录，按 App Store 4.8 必须同时补 Sign in with Apple**。本版 iOS 不接微信 SDK，只走手机号 → 豁免 |

## 2. 🔴 先澄清一件事：这和 `/v1/wx/*` 不是一回事

#2835 里已有 `/v1/wx/bind`、`/v1/wx/token`、`/v1/wx/revoke`，那三个是 **设备凭证**（证明「这台相机是你的」，产出 `wxt_`/`tcd_`）。

本文要的是 **账号凭证**（证明「你是谁」，产出 `acc_`/`ref_`）。两者并存、互不替代：

| 凭证 | 回答什么问题 | 路径 | 有效期 |
|---|---|---|---|
| `tcd_` / `wxt_` | 这台相机能不能读 | `/v1/wx/bind`（已上线） | device_secret 长期 / access 10 分钟 |
| `acc_` / `ref_` | 这个用户是谁 | `/v1/auth/wx`（**本文新增**） | access 10 分钟 / refresh 30 天轮换 |

**不要**把微信登录塞进 `/v1/wx/*` 命名空间，也不要复用 `device_secret` 表 —— 量级和语义都不同。

## 3. 需要新增的接口

### 3.1 `POST /v1/auth/wx` —— 微信登录（P0）

```
POST /v1/auth/wx
Content-Type: application/json

{ "code": "<wx.login 返回的 code>",
  "device_id": "<可选，当前设备，用于登录后建立 账号↔设备 关系>" }

200:
{ "code": 0,
  "data": {
    "access": "acc_xxx",              // 或 access_token，客户端两种都认
    "refresh": "ref_xxx",             // 或 refresh_token
    "expires_in": 600,
    "is_new": true,                   // 首次登录建号
    "account": { "id": "<uuid>", "nickname": "", "avatar": "", "phone": "" }
  } }
```

服务端实现：
1. `GET https://api.weixin.qq.com/sns/jscode2session?appid=&secret=&js_code=&grant_type=authorization_code`
2. 取 `openid`；若小程序已绑定开放平台账号还会返回 `unionid`，**有就一起存**（后续 App 接微信登录靠 unionid 合并账号，避免重复建号）
3. `openid` 唯一索引 → 命中即登录，未命中建号（`is_new: true`）
4. 发 `access` + `refresh`（沿用 #2835 §5 的 refresh 轮换规则：同一 refresh 二次使用判定泄露，撤销该账号全部 refresh）

🔴 错误码（沿用现有 4xxxx）：

| 场景 | 码 |
|---|---|
| `code` 为空 / 无效 / 已用过（code 一次性，5 分钟有效） | `40105` |
| 微信侧返回 `errcode 40163`（code been used） | `40105`，文案「请重试」 |
| 频控（同 openid 10 次/分，同 IP 60 次/分） | `40102` |
| access 失效 | `40103` |
| refresh 失效/复用 | `40104` |

🔴 安全红线：
- **`session_key` 绝不能返给前端**（它能解微信加密数据，等于给了用户任意解密能力）。只留在服务端
- **`appsecret` 只在服务端**。前端产物里不能出现，任何形式都不行
- `openid` 不要返给前端（前端不需要，返了等于送一个可枚举的标识）
- 频控按 openid + IP 双维度，`40102` 时**不要**区分「账号是否存在」（防枚举）

### 3.2 `POST /v1/auth/wx/phone` —— 绑定手机号（P1，可与 3.1 同批）

```
POST /v1/auth/wx/phone      Authorization: Bearer acc_xxx
{ "code": "<button open-type=getPhoneNumber 回调里的 code>" }

200: { "code": 0, "data": { "phone": "138****0000" } }
```

服务端用 `code` 调 `phonenumber.getPhoneNumber` 换号码（**不是** `jscode2session`，两种 code 不能混用）。

🔴 前置依赖（卡在这，需要运营动作）：
- 小程序需开通 **「手机号快速验证」** 权限（企业主体，0.03 元/次）
- 未开通时前端 `getPhoneNumber` 回调拿不到 `code`，客户端已按此做了降级提示（`mp_login_phone_todo`）

### 3.3 `PATCH /v1/auth/profile` —— 昵称 / 头像（P1，可延后）

```
PATCH /v1/auth/profile      Authorization: Bearer acc_xxx
{ "nickname": "小明", "avatar_url": "https://..." }
```

🔴 为什么需要：微信自 2022-10-25 起**不再返回昵称头像**（`wx.getUserProfile` 已收回）。小程序只能用
「头像昵称填写能力」让用户自己填（`open-type="chooseAvatar"` + `<input type="nickname">`），
拿到的是本地临时文件路径，**必须上传到我们自己的存储**才能跨设备看到。

当前客户端做法：昵称/头像先存本地（`tc.acctProfile`），接口就绪后改调本接口。这是已知缺口，不假装已同步。

## 6. 验收清单（请按此自测）

| # | 场景 | 通过条件 |
|---|---|---|
| 1 | 首次登录 | 新 openid → 建号，返回 `is_new: true` + 可用 access |
| 2 | 二次登录 | 同 openid → 不建新号，`account.id` 不变 |
| 3 | code 复用 | 同一 code 第二次提交返 `40105`，不建号 |
| 4 | 无 code | 返 `40105`，不返 500 |
| 5 | 过期 | access 过 10 分钟返 `40103`；用 refresh 能换到新对，旧 refresh 立刻失效 |
| 6 | refresh 复用 | 旧 refresh 二次使用返 `40104` 且撤销该账号全部 refresh |
| 7 | 密钥缺失 | 响应里**没有** `session_key`、`openid`、`appsecret` |
| 8 | 频控 | 同 openid 1 分钟内第 11 次返 `40102` |
| 9 | 登录带 device_id | 账号↔设备关系建立，且**不产生重复卡**（卡片仍归 device_id） |
| 10 | 手机号绑定 | 合法 code 换到手机号；已绑定时重复绑定不报 500 |
| 11 | 与设备凭证隔离 | 用 `acc_` 调 `/v1/wx/token` 必须失败；用 `wxt_` 调 `/v1/auth/refresh` 必须失败 |
