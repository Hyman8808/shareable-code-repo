## 0. 需求拆解：五条要求对应五个技术命题

| # | 产品要求 | 技术命题 | 责任方 | 本版状态 |
|---|---|---|---|---|
| 1 | 一台设备适配海内外，**硬件与固件不改**，由 App 设参数、云端按参数下发 | 语言与存储策略必须成为**设备可持久化的配置**，而不是编译期常量；设备要把它上报云端 | 固件（存参数）+ App（写参数）+ 云端（按参数取数） | App 侧已实现（v2.7.0）；**协议与云端待开发** |
| 2 | 物品语言选哪个，**设备界面语言就变哪个**（含提示、开机） | 设备 UI 需要**多语言资源包**，且可从配置切换；字形/字库是硬约束 | 固件（资源包）+ App（下发） | 协议已定义；**固件资源包待开发** |
| 3 | 云端存储默认 **7 天**，要延长按空间×时长付费 | 记录必须有 TTL 与清理策略；订阅要能改变单设备 TTL | 云端（必须） | **云端待开发**；App 已有入口与说明 |
| 4 | 美化额度 **10张/5元、50张/20元、100张/30元、500张/100元** | 定价、订单、扣减、对账、防刷；点卡而非订阅 | 云端（订单/支付）+ App（展示/调起） | App 档位已改（v2.7.0）；**支付与订单待开发** |
| 5 | 全球访问 **2 秒内** | 多区域接入 + 就近解析 + 边缘缓存 + 客户端超时/重试/预取 | 云端（主）+ 客户端（辅） | App 已加耗时可观测；**接入与缓存待开发** |

**一句话结论**：这五条里有四条卡在云端，一条卡在固件。App 能做的部分是"把参数写对、把话说明白、把耗时量出来"，已经在 v2.7.0 落地；**真正的工作量在云端六件事上**（注册系统、设备归属、语言配置、存储订阅、计费、全球接入），第 4、5 章逐项展开到接口级。

## 1. 业务模型的变化

### 1.1 三个"语言"必须分开看

这是本版最容易做错的地方。产品口语里的"语言"实际有三个，混在一起会导致"我明明选了日语，设备还是英文"这类无解 bug。

| 维度 | 谁决定 | 影响什么 | 存哪里 | 当前实现 |
|---|---|---|---|---|
| **物品语言** `item_lang` | App 设备设置 | 云端返回的译名、TTS 语种 | 设备 NVS + 云端设备表 | App 已写入（`DeviceLangStore` + BLE `0x12`） |
| **设备界面语言** `ui_lang` | 默认跟随物品语言 | 设备提示音/开机字幕/按键提示 | 设备 NVS + 固件资源包 | 同上，一次下发两个 TLV |
| **App 界面语言** | App 设置 | App 文案（中/繁/英） | App SP | 已有（`setApplicationLocales`） |
| （附）**名称显示语言** | App 名称语言（17 项） | App 内卡片显示用哪种译名 | App SP + `NameStore` | 已有 |

> ⚠️ **产品口径建议**：物品语言与 App 名称语言默认联动（选日语 → 云端取日语 → App 显示日语）。二者解耦只在"成人自用、只练听力"这类场景有意义，当前不暴露，避免用户配出"设备日语、App 英语"的错位。

### 1.2 一块硬件卖全球：把国家差异从固件里挪出来

```
            ┌──────────── 同一版固件 / 同一块板 ────────────┐
日本市场 ──►  item_lang=ja  ui_lang=ja  cloud_days=7   ──► 云端返回 英名+英TTS(默认) / 日名+日TTS
德国市场 ──►  item_lang=de  ui_lang=de  cloud_days=30  ──► 云端返回 英名+英TTS(默认) / 德名+德TTS
国内     ──►  item_lang=zh  ui_lang=zh  cloud_days=7   ──► 云端返回 中文名+中文TTS（源语言，无需翻译）
```

三条设计原则：

| 原则 | 理由 |
|---|---|
| **固件零分支** | 每多一版固件就多一条产线、测试、OTA 分支；语言若编进固件，出货前必须知道去哪个国家 |
| **配置可重写** | 同一台设备可以改配到另一市场（退货翻新、渠道调货），App 改一次即可，不用返厂重烧 |
| **默认可用** | 没有配置时按 `en` 工作，任何环节缺失都不会让设备变砖 |

### 1.3 免费 7 天 + 订阅存储

| 项 | 规则 |
|---|---|
| 默认保留 | **7 天**（免费，无需登录、无需订阅） |
| 到期行为 | 云端清理记录与原图，**已下载到手机的不受影响**（App 侧必须这么说，否则用户会以为照片全丢） |
| 延长方式 | 按"存储空间 × 时长"订阅，月付或年付 |
| 计费锚点 | 订阅绑**账号**，作用于该账号下所有设备；解绑/换机不丢 |
| 降级 | 订阅到期后回到 7 天，**不立即删**：给出 7 天宽限期，期间可续费恢复 |

> 🔴 **必须避免的实现**：按"设备"卖存储。设备是硬件、账号是长期资产，绑设备会导致换机后用户认为"钱白花了"，且无法在多设备间共享。

### 1.4 美化点卡定价

| 档位 | 价格 | 单价 | 适用 |
|---|---|---|---|
| 10 张 | ¥5 | ¥0.50/张 | 先试几个词 |
| 50 张 | ¥20 | ¥0.40/张 | 一个学期的量 |
| 100 张 | ¥30 | ¥0.30/张 | 一学年够用 |
| 500 张 | ¥100 | ¥0.20/张 | 多台设备 / 机构 |

**为什么用点卡而不是订阅**：美化是"按需、非连续"的行为（一个词通常只美化一次，之后长期不再消耗），订阅会造成"这个月没拍，钱照扣"的负面体验。点卡天然对应"一次性买断一批"的心理账户，也更适合作为硬件之外的加购项。

### 1.5 SLA：全球 2 秒

| 指标 | 目标 | 口径 |
|---|---|---|
| 首页首屏出卡片 | **P95 ≤ 2s** | 冷启动到首张卡片可见（本地有缓存时不拉网络） |
| 记录列表接口 | **P95 ≤ 800ms** | 服务端处理 + 网络（不含 App 渲染） |
| 单张 AI 出图 | 60–111s（现有实测） | 异步任务，不计入 2s 指标，但**必须有进度与后台续跑** |
| 词典查询 | P95 ≤ 1.5s | 已有 8s 超时兜底 |

## 2. 总体架构 V3.0

### 2.1 从"直连云端"到"账号 + 六个服务域"

V2.0 的架构是 **App 直连 nglearn + apikey**（因为不自建服务端）。V3.0 必须改：一旦有注册、订阅、点卡，apikey 模式就不成立了 —— 凭据无法证明"这台设备是谁的"，也无法记账。

```
                    ┌──────────────────────── 云端（新建） ────────────────────────┐
                    │ ① 账号域  注册/登录/token/注销                                 │
                    │ ② 设备域  绑定归属/换绑/多设备/配置(item_lang,ui_lang,days)    │
                    │ ③ 内容域  记录列表(按 lang)/详情/删除/TTL 清理                  │
                    │ ④ 语言域  译名管线/译名缓存/双 TTS                              │
                    │ ⑤ 存储域  订阅/容量计量/续费/降级                               │
                    │ ⑥ 计费域  点卡订单/支付回调/扣减/对账/防刷                       │
                    │ ⑦ AI 网关 方舟密钥托管/限流/内容安全                             │
                    └───────▲───────────────────▲──────────────────────▲─────────────┘
        HTTPS + token    │                   │ HTTPS(apikey+lang)   │ 就近接入
   ┌──────────────┐      │            ┌──────┴──────┐        ┌──────┴──────┐
   │     App      │──────┘            │  W800 设备   │        │  多区域节点  │
   │ 语言/额度/订阅│◄── BLE 0x12 ─────►│ 存 item/ui   │        │ cn/sea/eu/us │
   └──────────────┘    下发配置         └─────────────┘        └─────────────┘
```

### 2.2 语言参数在三端的流转（本版最关键的一条链）

```
① 用户在 App 选「日语」
        │
        ▼
② DeviceLangStore 落本地（item_lang=ja, ui_lang=ja, pending=true）
        │
        ▼  下一次配网 / 连上设备
③ BLE 0x12 下发 TLV(0x10=ja, 0x11=ja, 0x12=保留天数)
        │
        ▼
④ 设备写 NVS，重启后仍生效；并把 lang 带给云端
        │
        ▼
⑤ 云端按 item_lang 返回：
      name_english + tts_url_english        ← 恒定默认，任何市场都有
      name_localized(=ja) + tts_url_localized ← 目标语言
        │
        ▼
⑥ App 渲染：英文主名 + 日文副名/释义；设备朗读英/日两套 TTS
```

**关键点**：云端**永远返回英文**，再叠加目标语言。这不是冗余，而是为了三件事：a) 目标语言翻译失败时能立刻回退；b) 用户随时能听到英文（学英语是核心场景）；c) 译名质量不一致时不至于整条记录不可用。

### 2.3 端云职责边界

| 能力 | 只能云端做 | 只能端上做 | 说明 |
|---|---|---|---|
| 账号 / 订阅 / 订单 | ✅ | — | 涉及钱与身份，客户端无信任基础 |
| 译名生成与缓存 | ✅ | — | 多语言翻译需统一术语与质量抽检 |
| 记录 TTL 清理 | ✅ | — | 端上删了云端还在，等于没删 |
| 语言配置**存储** | ✅ | — | 换机/重装后要能恢复 |
| 语言配置**写入设备** | — | ✅ | 只有 App 有 BLE 通道 |
| 时延感知与降级 | — | ✅ | 网络状况只有端上知道 |
| 本地缓存与离线可读 | — | ✅ | 断网可用是产品底线 |
| AI 出图代理 | ✅ | — | 密钥不能进 APK（V2.0 遗留阻塞项） |

### 2.4 为什么不做"多固件"（备选方案否决记录）

| 方案 | 否决理由 |
|---|---|
| 按国家出不同固件 | 产线要按目的地分箱、库存不能调拨、OTA 要维护 N 条分支；一旦某国加语言就要全量回归 |
| 设备本地菜单选语言 | 无屏或小屏设备选 17 种语言是灾难；且用户第一次开机就要面对语言选择，转化率最低 |
| 语言写在 SD/配置文件 | 增加产线工序与不良率，且文件易被篡改 |
| **App 配参 + 云端取数（本方案）** | 固件一条分支；改市场只需 App 一次操作；参数可被云端覆盖（订阅变更时） |

## 3. 全球化语言架构

### 3.1 支持语言（与 App 名称语言同一套 17 项）

| 代码 | 语言 | 备注 |
|---|---|---|
| `en` | 英语 | **恒定默认**，任何语言下都返回 |
| `zh` | 简体中文 | 源语言，无需翻译（识物接口原生中文） |
| `zh-TW` | 繁体中文 | 端上由 `HantConverter` 本机转换，**云端不必单独出繁体** |
| `ja` `ko` | 日 / 韩 | 日文需注意汉字字形差异（见 §3.6） |
| `ru` `fr` `de` `pt` `th` `id` `vi` `es` `it` `ms` `fil` | 俄法德葡泰印尼越西意马菲 | 常规拉丁/西里尔/泰文 |
| `ar` | 阿拉伯语 | **RTL**，端上与设备都要镜像 |

### 3.2 一次识别的返回契约（云端改造核心）

现状：`/api/record/list` 返回 `name_chinese` / `name_english` / `information` / `tts_url` / `tts_url_english`，**与设备语言无关**。

V3.0 要求（字段名沿用现有风格，避免端上大改）：

```jsonc
{
  "id": 12345,
  "device_id": "c8586a630000",
  "image_url": "...",
  "name_english": "Iced Drink",              // 恒定
  "tts_url_english": ["...mp3"],             // 恒定
  "name_localized": "アイスドリンク",          // 按 item_lang；zh 时等于 name_chinese
  "name_localized_lang": "ja",               // 回显，端上必须校验一致才用
  "tts_url_localized": ["...ja.mp3"],        // 按 item_lang；zh 时为中文 TTS
  "information": {
    "phonetic": "/aɪst drɪŋk/",              // 英文音标，恒定
    "description_localized": "氷を入れた飲み物"  // 可选，按 item_lang
  },
  "localized_status": "ok",                  // ok / pending / fallback / unsupported
  "create_time": "2026-10-23 10:00:00",
  "expire_at": "2026-10-30 10:00:00"         // 新增：该记录的云端到期时间（7 天或订阅延长）
}
```

| 新增/变更字段 | 作用 | 端上处理 |
|---|---|---|
| `name_localized` / `name_localized_lang` | 目标语言译名 + 回显 | **必须校验回显语言等于请求语言**，否则视为未翻译（V2.0 已按此实现 `persistLocalizedNames`） |
| `tts_url_localized` | 目标语言 TTS | 为空则退回英文 TTS，**不报错** |
| `localized_status` | 翻译质量状态 | `pending` 显示英文 + "翻译中"；`fallback` 显示英文（可见回退）；`unsupported` 隐藏该语言选项 |
| `expire_at` | 云端到期时间 | 列表上对 ≤2 天的记录打"即将清理"提示，引导存本地或订阅 |
| `information.description_localized` | 释义本地化 | 缺省时显示英文/中文原释义，不阻塞 |

> 🔴 **`localized_status` 是本版新增的硬要求**。没有它，端上无法区分"还没翻完"与"这个词没有该语言"，只能统一显示英文，用户会认为"日语模式没生效"。

### 3.3 参数下发链路（App → 设备 → 云端）

```
App                      设备                    云端
 │                        │                       │
 │ ① BLE 0x12 下发         │                       │
 │   item_lang/ui_lang    │                       │
 │   cloud_days           │                       │
 ├───────────────────────►│                       │
 │                        │ ② 写 NVS（掉电不丢）    │
 │                        │                       │
 │                        │ ③ 识别上报：           │
 │                        │   deviceId, apikey,    │
 │                        │   item_lang, ui_lang   │
 │                        ├──────────────────────►│
 │                        │                       │ ④ 按 item_lang 生成译名+TTS
 │                        │ ⑤ 返回双语结果         │
 │                        │◄──────────────────────┤
 │ ⑥ 拉列表时带 lang=ja    │                       │
 │   （App 展示用）         │                       │
 ├───────────────────────────────────────────────►│
```

**双通道的必要性**：设备自己拍照时必须知道语言（它要朗读、要显示），所以设备必须持有该参数；App 拉列表时也要带 `lang`（用户可能在 App 里切换显示语言，且 App 可能管理多台设备）。

### 3.4 设备配置协议 `0x12`（新增，需固件实现）

**命令**：`0x12` DEVICE_CONFIG（App→设备）/ `0x92` 响应（设备→App，可选）

| TLV | 名称 | 长度 | 值 |
|---|---|---|---|
| `0x10` | ITEM_LANG | 2–8 B | ASCII，BCP-47 短码（`ja` / `zh` / `zh-TW` / `en` / `ar`） |
| `0x11` | UI_LANG | 2–8 B | 同上；固件若无该语言资源包→回退 `en` 并在 `0x92` 标记 |
| `0x12` | CLOUD_STORE_DAYS | **2 B 小端** | 7 / 30 / 365。⚠️ 单字节会截断（365→109），必须 2 字节 |
| `0x81` | RESULT（0x92 中） | 1 B | 0 成功 / 1 不支持的语言 / 2 资源包缺失 / 3 参数非法 |

**时序与容错**：

| 场景 | 处理 |
|---|---|
| 设备不支持 `0x12` | 不回 `0x92`。App 侧**帧写出即视为完成**（`markApplied`），不可因此判定配网失败 |
| 写入失败（分片超时） | 保留 `pending=true`，下次连上设备自动重发 |
| 重复下发 | 设备必须**幂等**：同值直接回成功，不重启、不清记录 |
| 下发时机 | ① 配网绑定成功后；② 用户在 App 改语言后（若设备已连）；③ 订阅变更后（云端→App→设备） |
| 长度校验 | 固件对超长（>8B）或非 ASCII 参数应回 `0x81=3`，不得写入 NVS |

**为什么天数用 TLV 而不是让设备问云端**：设备只在拍照时联网（省电），开机/离线时也要知道"本地还能留多久"以便提示存储；且订阅到期时云端可通过 App 主动改短。

### 3.5 设备界面语言（固件资源包）

设备界面语言不是"云端下发文案"，而是**固件内置资源包 + 运行期选择**。原因：开机动画、无网提示、电量提示都发生在没有网络的时候，不能依赖云端。

| 界面元素 | 是否需本地化 | 备注 |
|---|---|---|
| 开机 Logo 字幕 | ✅ | 语言切换后下次开机生效 |
| 拍照/上传/成功/失败提示音与字幕 | ✅ | 最常见，优先覆盖 |
| 电量、存储、Wi-Fi 状态 | ✅ | 图标为主，文字为辅 |
| 语音播报（TTS） | ❌ | 走云端 TTS，无需内置 |
| 配网引导 | ✅ | 首次开机最需要 |

**资源包体积估算**（需固件侧确认）：

| 语言 | 文本资源 | 字形点阵/字库 | 小计 |
|---|---|---|---|
| 英文 | ~4KB | 内置 | 4KB |
| 中文（简/繁共用字库） | ~6KB | 3–4MB（16×16 点阵可降至 ~1MB） | 1–4MB |
| 日文 | ~6KB | 含汉字，可与中文共用部分 | +1–3MB |
| 韩文 | ~5KB | 谚文字形 | +0.5MB |
| 阿拉伯/泰文 | ~5KB | 需连写/上下标支持 | +0.3MB |

> ⚠️ **这是本版最大的固件风险**：若 Flash 余量不足，只能"中英日韩 + 拉丁"五类资源包，其余语言界面退回英文（物品语言仍可 17 种，因为那是云端文本）。必须尽早量出 Flash 余量。

### 3.6 多语言的工程坑（交付前必须过一遍）

| 坑 | 影响 | 处理 |
|---|---|---|
| 日文汉字与中文汉字字形不同（骨/直/真） | 同一字库显示"像中文的日文" | 日文单独字库或采用 Unicode 变体选择 |
| 泰文上下标叠加 | 行高被撑高，按钮文字溢出 | 固定行高 + 允许裁切，UI 预留 1.3 倍行高 |
| 阿拉伯语 RTL | 数字/标点位置错乱 | 整体镜像 + 数字用 LTR 隔离 |
| 德语/俄语长词 | 按钮文字截断 | 按钮宽度按最长语言设计，或允许两行 |
| 越南语声调符号 | 点阵字库覆盖不全 | 字库需含预组合字符 |
| 印尼/马来语高度相似 | 翻译供应商可能混用 | 术语表分开维护 |

### 3.7 降级与回退（三级）

| 级别 | 触发 | 用户看到 | 设备行为 |
|---|---|---|---|
| L1 正常 | 云端有目标语言译名 + TTS | 英文 + 目标语言 | 双语朗读 |
| L2 回退 | 译名成功但 TTS 缺失 | 英文 + 目标语言（无朗读） | 只播英文 |
| L3 兜底 | 译名失败/超时/不支持 | 只有英文 + 一行"该语言暂未支持" | 只播英文 |
| L4 离线 | 无网 | 本地缓存（上次结果） | 播本地缓存的 MP3 |

**不允许的行为**：显示空白、显示占位符、静默切成中文（用户会以为买到了国内版）。

### 3.8 App 侧已实现（v2.7.0）

| 项 | 实现 |
|---|---|
| 设备语言设置入口 | 我的 → 设备语言（17 项，英语置首，`NONE` 不出现） |

| 反馈文案 | 设置时明确"下次连接设备时自动下发" |

## 4. 云端待开发能力（本版重点）

### 4.1 能力矩阵：现在有什么、缺什么

| 域 | 现状 | 缺口 | 优先级 |
|---|---|---|---|
| 账号 | **无**（App 登录页占位） | 注册/登录/Token/注销/合规 | **P0** |
| 设备归属 | **无**（apikey 整批公用，任意 deviceId 可查） | 绑定归属、换绑、多设备 | **P0** |
| 内容 | 有 `/api/record/list`、`/detail`（无 lang、无删除、无 since_id） | 按语言返回、TTL、删除、增量 | **P0** |
| 语言 | **无**（只有中文名 + 英文名） | 译名管线、译名缓存、TTS 多语、状态字段 | **P0** |
| 存储订阅 | **无** | 容量计量、套餐、续费、降级 | P1 |
| 计费 | **无** | 点卡订单、支付回调、扣减、对账、防刷 | P1 |
| AI 网关 | **无**（密钥在 APK 里，直连方舟） | 密钥托管、限流、内容安全 | **P0（安全）** |
| 全球接入 | 单区域（国内） | 多区域、就近解析、边缘缓存 | P1 |

### 4.2 账号与注册系统（P0，必须从零建）

**为什么必须先做账号**：订阅绑账号、点卡绑账号、设备归属绑账号。没有账号，后面三件事都无法记账，"7 天 / 订阅 / 点卡"全是空话。

| 能力 | 说明 |
|---|---|
| 注册/登录 | 手机号验证码（国内）、邮箱 + 验证码（海外）、Apple / Google 登录（海外上架必需） |
| Token | 短期 access（2h）+ 长期 refresh（30d），refresh 轮换 |
| 注销 | 应用商店合规要求（Apple 5.1.1(v) / Google Play），必须能注销且清数据 |
| 游客模式 | **必须允许**：不登录也能配网拍照、看 7 天记录；登录后才享订阅与跨设备 |
| 多端 | 同一账号多台手机、多台相机；**不限制同时在线**，但限制单账号设备数（建议 ≤5） |
| 合规 | 儿童用户需家长同意流程（COPPA / 个保法）；隐私政策分区域版本 |

> 🔴 **游客模式是硬要求，不是可选项**：硬件开箱即用如果先要求注册，退货率会明显上升。产品路径必须是"先能用 → 再引导登录换权益"。

### 4.3 设备域（P0）

| 能力 | 说明 | 为什么必须 |
|---|---|---|
| 绑定归属 | `deviceId` → `userId` 一对一（或一对多家庭共享） | 现在任意 apikey 持有者可枚举任何设备记录，是**安全红线** |
| 绑定动作 | App 用 apikey + deviceId 换一个**绑定票据**（云端签发），后续接口用票据不用 apikey | apikey 泄露面收敛 |
| 换绑 | 原机主解绑后 7 天内可抢回；超过则释放 | 二手交易与误操作 |
| 多设备 | 一个账号下 N 台相机，各自独立语言/存储 | 家庭场景（俩孩子各一台） |
| 配置存储 | 云端保存每台设备的 `item_lang` / `ui_lang` / `cloud_days` | 换手机后能恢复，且云端可反向修正设备 |
| 设备上报 | 设备每 24h 上报一次配置快照（离线队列） | 云端要知道设备真实状态，不能只信 App |

### 4.4 内容域（P0）

| 改造 | 现状 | 目标 |
|---|---|---|
| `lang` 参数 | 端上已传，**云端未实现** | 按 `lang` 返回 `name_localized` / `tts_url_localized` / `localized_status` |
| TTL | 无 | 每条记录带 `expire_at`；定时任务清理；清理前 48h 通知（App 内提示） |
| 删除 | 无接口 | `DELETE /v1/record/{id}`，同时删 OSS 原图 |
| 增量 | 无 `since_id` | 支持 `since_id`，端上不再靠"整页命中"猜边界 |
| 排序 | 未声明 | 明确 `id DESC` 并写进文档 |
| 图片 | OSS 直链，无尺寸参数 | 支持 `?w=400` 缩略图，减少海外首屏流量 |

### 4.5 语言域：译名管线（P0）

设备拍完照，云端识别得到中文名 + 英文名，**需要在写入记录时就生成目标语言译名**（同步或异步）：

```
识别完成（中文+英文）
   │
   ├─ item_lang = zh → 直接用中文，localized_status=ok
   ├─ item_lang = en → 英文即目标语言，重复利用，ok
   └─ 其他语言
        ├─ 查译名缓存（按 英文名 + lang，命中即用）
        ├─ 未命中 → 机器翻译 + 术语表约束（品牌名/专有名词不译）
        ├─ TTS 合成（按 lang 选择发音人；日/韩/泰需对应音色）
        └─ 写记录，localized_status=ok / pending
```

| 要求 | 理由 |
|---|---|
| 译名缓存按"英文名 + 语言"而非"记录 id" | 同一个 `Iced Drink` 被拍 100 次只翻一次，省成本 |
| 术语表约束 | `iPad` / `Nike` 不能被译成奇怪的中文 |
| 低置信度不写库 | 宁可 `fallback` 显示英文，也不要给用户一个错误译名 |
| 支持人工修正 | 运营后台可覆盖某条译名，且覆盖要进缓存 |
| 同义词去重 | `iced drink` / `ice drink` 归一后再翻译 |

### 4.6 存储与订阅域（P1）

| 能力 | 说明 |
|---|---|
| 容量计量 | 按 `sum(原图字节)` 计算每账号占用；缩略图不计或按 10% 计 |
| 套餐 | 按"空间 × 时长"：如 50GB/月、200GB/月、1TB/年（**价格待商务定**） |
| 生效 | 订阅生效 → 该账号下所有设备 `cloud_days` 提升（30/365）→ 通过 App 下发到设备 |
| 续费提醒 | 到期前 7/3/1 天推送；到期后 7 天宽限（只读不删） |
| 降级 | 宽限期结束 → 记录按 7 天 TTL 清理；**已下载到手机的不受影响** |
| 退款 | 未使用按比例退（需与支付渠道规则一致） |

### 4.7 计费域：点卡（P1）

| 环节 | 要求 |
|---|---|
| 下单 | `POST /v1/ai/order`（tier=10/50/100/500），返回渠道支付参数 |
| 支付 | 国内微信/支付宝，海外 Apple IAP / Google Play Billing（**上架硬要求**） |
| 回调 | 校验签名 + 幂等（同一订单重复回调只加一次） |
| 入账 | 加到**账号**而非设备；多设备共享同一份余额 |
| 扣减 | 生成前校验余额，**出图成功后扣**（失败不扣），并发扣减需原子 |
| 对账 | 日对账：渠道流水 vs 入账记录 vs 消耗记录 |
| 防刷 | 单账号日生成上限、异常频次风控、同图重复生成冷却（如 10 分钟内同图不重复扣） |
| 退款 | 未消耗张数可按比例退；已消耗不退 |

### 4.8 AI 网关（P0，安全）

现状：`BuildConfig.ARK_API_KEY` 编在 APK 里，任何人反编译即可取出，直接刷爆账号额度。

| 改造 | 说明 |
|---|---|
| 密钥托管 | 方舟密钥只在服务端；App 调 `/v1/ai/generate`，服务端代调 |
| 鉴权 | 用账号 token + 额度校验，**App 不再持有任何云厂商密钥** |
| 限流 | 单账号 QPS + 日上限；防批量刷 |
| 内容安全 | 生成结果过审（尤其面向儿童） |
| 异步化 | 长任务改"提交 → 轮询/推送"，避免 App 持 300s 连接（现有做法在弱网下易断） |

> 这一项与"注册系统"同为 P0：**只要 APK 发出去，密钥就等于公开**。v2.7.0 之前的所有包都不能对外分发。

### 4.9 全球接入（P1）

| 要求 | 做法 |
|---|---|
| 多区域部署 | 至少 3 个区域：中国大陆、东南亚（新加坡）、欧洲（法兰克福）；北美按需 |
| 就近解析 | GeoDNS 或 Anycast；**不要**用单一 `*.turingapi.com` 全球回源国内 |
| 数据驻留 | 欧盟用户数据留在欧盟（GDPR）；跨境需 SCC |
| 图片 CDN | OSS 挂 CDN，边缘缓存 7 天，缩略图按需生成 |
| 边缘缓存 | 记录列表短缓存（30s，按 deviceId+lang 分键），减少回源 |
| 连接效率 | HTTP/2 + keep-alive，TLS1.3 会话复用，避免每请求重新握手 |

### 4.10 可观测（P1）

| 指标 | 用途 |
|---|---|
| 接口 P50/P95/P99（按区域 × 接口 × 语言） | 定位是哪一段慢 |
| 翻译成功率 / `fallback` 率（按语言） | 判断语言是否真的"支持" |
| TTS 命中率（缓存） | 成本控制 |
| 订阅转化 / 点卡 ARPU | 商业健康度 |
| 清理任务成功率 | 防止"说 7 天其实没删" |

## 5. 云端协议设计（接口级）

> 本章是给云端团队的**施工图**。命名沿用现有 `/api/` 风格但升级到 `/v1/`，避免与旧接口混淆；旧接口保留 6 个月过渡。

### 5.1 通用约定

| 项 | 约定 |
|---|---|
| Base | `https://api.<region>.thumbcard.com/v1`（区域：`cn` / `sea` / `eu`） |
| 鉴权 | `Authorization: Bearer <access_token>`；设备侧仍用 `apikey` + `deviceId`（兼容旧固件） |
| 内容类型 | `application/json; charset=utf-8` |
| 幂等 | 写操作带 `Idempotency-Key`（订单、绑定） |
| 时间 | 全部 UTC，返回 ISO8601 带时区 |
| 分页 | `page`（从 1）/ `size`（≤100）/ 返回 `total` |
| 错误 | `{"code": 40101, "message": "...", "trace_id": "..."}`，`trace_id` 必须透出，便于联调 |
| 版本 | 路径版本 + 灰度开关（按 deviceId 哈希） |

**错误码分段**：

| 段 | 含义 | 示例 |
|---|---|---|
| 2xxxx | 成功/通用 | 20000 成功 |
| 400xx | 参数 | 40001 参数缺失、40002 语言不支持 |
| 401xx | 鉴权 | 40101 token 失效、40102 签名错误 |
| 403xx | 权限 | 40301 非本人设备、40302 已绑定他人 |
| 404xx | 资源 | 40401 记录不存在 / 已过期清理 |
| 409xx | 冲突 | 40901 已绑定、40902 订单重复 |
| 402xx | 余额/订阅 | 40201 张数不足、40202 订阅过期 |
| 5xxxx | 服务端 | 50001 翻译服务不可用、50002 TTS 失败 |

### 5.2 账号接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/auth/sms/code` | 发送短信验证码（含图形/行为验证防刷） |
| POST | `/auth/login/sms` | 手机号 + 验证码登录，返回 token |
| POST | `/auth/login/email` | 邮箱 + 验证码（海外主用） |
| POST | `/auth/login/oauth` | Apple / Google id_token 换取本系统 token |
| POST | `/auth/refresh` | refresh_token 换新 access（轮换旧 refresh） |
| GET | `/auth/profile` | 昵称、区域、语言偏好、订阅状态 |
| PATCH | `/auth/profile` | 改昵称 / 默认语言 |
| POST | `/auth/logout` | 注销当前 token |

### 5.4 记录接口（改造版）

```
GET /v1/record/list?deviceId=c8586a630000&lang=ja&page=1&size=100&since_id=0
```

| 参数 | 说明 |

返回字段见 §3.2。新增：

### 5.8 AI 接口（网关化）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/ai/generate` | 提交任务 `{cardId, style, sourceUrl}` → `taskId` |
| GET | `/v1/ai/task/{taskId}` | 轮询状态（pending/running/done/failed）+ 结果 URL |
| POST | `/v1/ai/cancel` | 取消（未开始的任务） |

**为什么改异步**：现有实现是 App 直连方舟并 hold 住 60–111 秒的连接。海外弱网下这是最脆弱的一段，且无法做限流与内容审核。改异步后 App 只需要轮询短请求，断网可续。

### 5.9 设备侧上报协议（设备 → 云端）

设备在识别上报时**必须新增两个字段**（固件改造项）：

```jsonc
{
  "device_id": "c8586a630000",
  "apikey": "...",
  "item_lang": "ja",       // 新增：决定返回语言
  "ui_lang": "ja",         // 新增：仅记录，便于运营统计
  "fw_ver": 17,
  "image": "<binary>"
}
```

| 兼容策略 | 说明 |
|---|---|
| 老固件不带 `item_lang` | 云端按 `en` 返回（英文 + 中文原名），行为与今天一致，**不报错** |
| 未知语言码 | 云端按 `en` 返回，并在响应里带 `localized_status=unsupported` |
| 设备上报的 lang 与云端配置不一致 | **以云端配置为准**（App 改过但设备没收到时，云端可纠正），并回写设备 |

### 5.10 时延预算（服务于 2 秒目标）

| 阶段 | 预算 | 手段 |
|---|---|---|
| DNS | ≤50ms | 就近权威、预解析、连接预热 |
| TCP + TLS | ≤120ms（会话复用 ≤20ms） | HTTP/2、TLS1.3、keep-alive |
| 服务端处理 | ≤200ms | 记录查询走索引、译名走缓存（不实时翻译） |
| 首字节（TTFB） | ≤400ms | 边缘缓存 30s |
| 传输 | ≤200ms（列表 ≤50KB） | 缩略图参数、字段裁剪 |
| 解析 + 首屏渲染 | ≤300ms | 端上先渲染缓存再刷新 |
| **合计** | **≤1.3s（留 35% 余量到 2s）** | |

## 6. 商业化：存储与美化

### 6.1 免费 7 天的实现要点

| 项 | 设计 |
|---|---|
| TTL 字段 | 每条记录 `expire_at = create_time + cloud_days`（写记录时算死，避免后续改配置影响历史） |
| 清理任务 | 每小时跑一次，分批删（每批 500 条），删记录 + OSS 原图 + TTS 缓存 |
| 提前提醒 | `expire_at - now ≤ 48h` 且未存本地 → App 列表打"即将清理"标记（需要端上知道"是否已存相册"，见 §7.6 后续项） |
| 订阅延长 | 订阅生效时**批量刷新该账号下所有记录的 `expire_at`**（不是只改配置，否则已存在的记录仍按旧时间到期） |
| 降级 | 到期后设 7 天宽限（只读），宽限期满按 7 天规则清理 |
| 幂等 | 清理任务重复执行不出错（按 `expire_at < now` 批量删） |

> 🔴 **最常见的实现错误**：只改"账号的 cloud_days"而不重算已有记录的 `expire_at`。表现是"我买了会员，老照片还是被清了"。

### 6.2 美化定价与毛利测算

| 档位 | 售价 | 单价 | 假设单张成本 ¥0.10 | ¥0.20 | ¥0.30 |
|---|---|---|---|---|---|
| 10 张 | ¥5 | ¥0.50 | 毛利 ¥4.0（80%） | ¥3.0（60%） | ¥2.0（40%） |
| 50 张 | ¥20 | ¥0.40 | ¥15（75%） | ¥10（50%） | ¥5（25%） |
| 100 张 | ¥30 | ¥0.30 | ¥20（67%） | ¥10（33%） | ¥0（0%） |
| 500 张 | ¥100 | ¥0.20 | ¥50（50%） | ¥0（0%） | **亏损** |

> ⚠️ **成本必须尽早核定**：Seedream 单张成本 + 存储 + 带宽 + 支付手续费（约 0.6%–2%）决定 500 张档是否成立。若单张成本 ≥0.20 元，500 张档（0.20/张）没有任何毛利，只能作为"拉高客单"的引流档，或者改为 500 张 ¥120–150。本表成本列为**假设值，待财务与方舟商务确认**。

**建议**：在成本未定前，把 500 张档做成"限时/限量"或"机构专享"，避免被批量采购打穿。

### 6.3 存储订阅（价格待商务定）

| 项 | 建议 |
|---|---|
| 计量 | 按"账号占用空间"（原图 + 缩略图按 10% 计） |
| 档位 | 50GB / 200GB / 1TB |
| 时长 | 月付 / 年付（年付约 8 折） |
| 区域定价 | 国内人民币、海外美元/欧元，按 `storage/plans` 下发 |
| 与美化的关系 | **两条独立产品线**：存储是"保照片"，美化是"做好看"，不要打包成一个大订阅（会互相拖累转化） |

### 6.4 为什么美化不做订阅（论证）

| 维度 | 点卡（选定） | 订阅（否决） |
|---|---|---|
| 使用频率 | 一个词通常只美化一次 | 与"按月"无对应关系 |
| 心理账户 | "买一批用完为止" | "每月扣钱但没怎么用" → 退订与差评 |
| 硬件加购 | 与硬件一起卖自然 | 硬件一次性 + 订阅持续，解释成本高 |
| 退款 | 未用可退，简单 | 按比例退，复杂且易争议 |

### 6.5 收入结构

```
单台收入 = 硬件毛利（保本）
         + 美化点卡（一次性，弹性大）
         + 存储订阅（持续，ARPU 低但留存长）
```

与 V2.0 的单位经济（单台贡献 66.25 元，含 6 元内购）相比，V3.0 把"内购"拆成两条线：点卡按 0.3–0.5 元/张定价，一个活跃家庭一年 50–100 张是合理区间（¥20–30）；存储订阅若定价 ¥6–12/月，年化 ARPU 约 ¥70–140，但转化率通常只有个位数。**结论：点卡是主要利润来源，订阅是留存工具，不要把收入预期压在订阅上。**

## 8. 2 秒访问的实现路径

### 8.1 时延分解与责任划分

| 段 | 典型耗时（跨境未优化） | 优化后 | 谁负责 |
|---|---|---|---|
| DNS 解析 | 80–300ms | ≤50ms | 云端（就近权威） |
| TCP 握手 | 100–300ms | ≤60ms | 云端（就近节点） |
| TLS 握手 | 150–400ms | ≤60ms / 0（复用） | 云端 + 客户端（keep-alive） |
| 服务端处理 | 100–800ms（若实时翻译） | ≤200ms | 云端（缓存译名、索引） |
| 传输 | 200–2000ms（大图直链） | ≤200ms（缩略图） | 云端（CDN + 尺寸参数） |
| 客户端解析渲染 | 100–300ms | ≤300ms | 客户端 |

**结论**：2 秒的瓶颈在"跨境 + 大图 + 实时翻译"，三个都在云端。客户端能贡献的是"别浪费"——不复用连接、超时过长、无缓存优先，都会把云端的优化吃掉。

### 8.2 六个手段（按性价比排序）

| # | 手段 | 收益 | 成本 |
|---|---|---|---|
| 1 | **图片走 CDN + 缩略图参数** | 最大（2MB → 80KB） | 低 |
| 2 | **多区域接入 + 就近解析** | 大（跨境 RTT 300ms → 30ms） | 中 |
| 3 | **译名缓存，不在请求链路里翻译** | 大（翻译 500ms → 0） | 低 |
| 4 | **边缘缓存列表 30s** | 中 | 低 |
| 5 | **HTTP/2 + keep-alive + TLS 复用** | 中（省 2 个 RTT） | 低 |
| 6 | 客户端"先渲染本地再刷新" | 中（感知时延） | 已实现 |

### 8.3 客户端降级策略

| 场景 | 行为 |
|---|---|
| 首屏有本地缓存 | 立即渲染（0 网络等待），后台静默刷新 |
| 请求超 3s 未回 | 显示缓存 + "同步中"，不弹错误 |
| 请求失败 | 保留缓存，顶部一条轻提示，不阻塞浏览 |
| 海外节点不可用 | 按区域配置切换备用域名，**只重试一次**（避免雪崩与电量消耗） |
| 图片加载失败 | 显示占位图，点击重试；不整页报错 |

### 8.4 度量与验收

| 指标 | 采集 | 验收 |
|---|---|---|
| 列表接口 P50/P95 | 服务端埋点 + App `LatencyStore` | 双端对得上才算数 |
| 首屏可见时间 | App 内打点（冷启动 → 首卡可见） | 目标机型 + 3 个区域各测 20 次 |
| 海外实测 | 新加坡 / 法兰克福 / 洛杉矶 三地探针 | P95 ≤2s；不达标不许上线区域 |

> 🔴 验收必须在**目标区域真机**上做。国内测 1.2s 不代表欧洲能进 2s —— 跨境 RTT 一项就能吃掉 600ms。

## 9. 兼容与风险

### 9.1 过渡期（固件未支持 `0x12`）

| 现象 | 处理 |
|---|---|
| 设备不响应 `0x12` | App 视为已下发（帧写出即完成），不阻塞配网；诊断页仍显示配置值 |
| 设备实际语言未变 | 在"设备语言"行下方**新增一行提示**（后续版本）："当前固件版本不支持语言切换，请联系售后升级" |

### 9.2 固件资源包体积（最大硬风险）

| 风险 | 说明 | 应对 |
|---|---|---|
| Flash 不足 | 中日韩字库吃掉 3–8MB | 先做"中英日韩 + 拉丁"，其余界面回退英文 |
| 字库授权 | 商业字库需授权 | 用开源字库（思源/Noto）并确认商用许可 |
| RTL 支持 | 阿拉伯语镜像布局工作量大 | 一期内不做阿语界面，仅做物品语言（云端文本） |

### 9.3 数据合规

| 区域 | 要求 | 影响 |
|---|---|---|
| 中国 | 个保法、儿童个人信息网络保护规定 | 儿童用户需监护人同意；数据境内存储 |
| 欧盟 | GDPR、数据驻留 | 欧盟用户数据留 EU；需 DPA、删除权 |
| 美国 | COPPA（13 岁以下） | 家长同意流程，不能默认收集 |
| 应用商店 | Apple 5.1.1(v) 账号删除、Google 数据安全表单 | 必须有注销账号入口 |

### 9.4 商业风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 500 张档毛利为负 | 见 §6.2 | 成本核定后再定，或改限量 |
| 订阅转化低 | 家庭用户对"存照片"付费意愿弱 | 不做主推，作为留存工具 |
| 退款争议 | 点卡已用不退 | 明确条款 + 未用可退 |
| 汇率与区域定价 | 海外价格需与商店档位对齐 | 价格云端下发，不硬编码 |

### 9.5 依赖链（关键路径）

```
云端账号 ──► 设备归属 ──► 记录按 lang 返回 ──► 订阅生效下发 ──► 点卡计费
```
