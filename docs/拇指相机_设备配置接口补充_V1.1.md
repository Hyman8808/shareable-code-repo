## 5. 设备配置：读取并纠正播报语言

### 5.1 这个接口解决什么

App 端改了语言（`PATCH /client/v1/devices/{id}`），云端只**存**下来，**不会主动推给设备**（没有 MQTT/WebSocket 通道）。
所以设备必须在合适时机主动来问一次：把自己的现状报上来，云端对比后告诉设备"你该用哪个"。

**这是拉取模型（pull），不是推送（push）。** 设备不问，语言永远不变。

### 5.2 请求

```
POST /v1/device/config
Authorization: Bearer <Device-Key>
Device-Id: cam-001
Content-Type: application/json

{"item_lang":"zh","ui_lang":"zh"}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `item_lang` | string | 是 | **设备当前**的物品语言（识别结果翻译成什么语言）。首次上电填出厂默认，一般 `zh` |
| `ui_lang` | string | 是 | **设备当前**的界面语言（屏上提示语、按键菜单） |

> ⚠️ 字段名是下划线风格的 `item_lang` / `ui_lang`。
> 传驼峰 `itemLang` / `uiLang` 或 `lang` **不会报错，但会被静默忽略**，云端认为"设备没上报"，`reported_*` 返回空串——排查时极易误判。

### 5.3 响应

```json
{"code":0,"data":{
  "deviceId":"cam-001",
  "item_lang":"ja",            // ← 云端权威值，设备要用这个
  "ui_lang":"ja",              // ← 云端权威值
  "reported_item_lang":"zh",   // ← 回显设备刚上报的值（空串=没解析到）
  "reported_ui_lang":"zh",
  "corrected":"true"           // ← true = 设备现状与云端不一致，需要切换
}}
```

**设备端处理逻辑：**

```
收到响应
├─ corrected == "true"
│    └─ 把本地 item_lang/ui_lang 改成响应里的值
│       ├─ 更新屏显/菜单语言（ui_lang）
│       ├─ 更新 TTS 播报语言（item_lang）
│       └─ 存 NVS/Flash，下次开机直接用，不用再问
└─ corrected == "false"
     └─ 什么都不做
```

### 5.4 什么时候该调（建议）

| 时机 | 必要性 | 理由 |
|---|---|---|
| 开机联网成功后 | **必须** | 覆盖"关机期间 App 改了语言"的场景 |
| WiFi 重连成功后 | 必须 | 同上 |
| 每次拍照识别前 | 建议 | 让"刚改的语言"立刻对下一张生效，用户感知最强 |
| 空闲时每 5~10 分钟 | 可选 | 缩短生效时延；注意功耗，建议只在插电/充电时做 |

> 产品口径：**"App 改语言后，设备下一次开机、或下一次拍照时生效"**。
> 如果要求"按下去立刻变"，只有两条路：① 设备保持长连接（W800 功耗不允许）；② App 走 BLE 直连下发（需要 App 有蓝牙，当前对方 App 没有）。

### 5.5 语言枚举（云端当前接受值，建议固件只认这 8 个）

| 值 | 语言 | 值 | 语言 |
|---|---|---|---|
| `zh` | 中文 | `fr` | 法语 |
| `en` | 英语 | `de` | 德语 |
| `ja` | 日语 | `ru` | 俄语 |
| `ko` | 韩语 | `es` | 西班牙语 |

> 云端目前**不做白名单校验**（传 `xx`、`EN`、`中文` 都会存进去）。固件若收到不认识的值，**按 `en` 兜底**，并把原值原样回报，不要崩。

### 5.6 错误码

| code | 含义 | 设备侧动作 |
|---|---|---|
| `0` | 成功 | 按 `corrected` 处理 |
| `40001` | 请求体不是合法 JSON | 检查 Content-Type 和 JSON 格式 |
| `40101` | Device-Key 或 Device-Id 不对 | 不要重试，等配网重刷 |
| `40401` | 设备不存在 | 提示"设备未注册"，走配网 |

### 5.7 联调自测（curl）

```bash
# 1. 改语言（App 侧，用运营发的 clientToken）
curl -sS -X PATCH "https://thumbcamera-api.turingapi.com/client/v1/devices/cam-001" \
  -H "Authorization: Bearer <clientToken>" -H 'Content-Type: application/json' \
  -d '{"lang":"ja"}'

# 2. 设备上报旧语言（用 Device-Key）
curl -sS -X POST "https://thumbcamera-api.turingapi.com/v1/device/config" \
  -H "Authorization: Bearer <Device-Key>" -H "Device-Id: cam-001" \
  -H 'Content-Type: application/json' -d '{"item_lang":"zh","ui_lang":"zh"}'

# 期望：corrected="true"，item_lang="ja"，reported_item_lang="zh"
```

## 6. 顺带修一处 v1 的口径

v1 §1 写"`lang` 是这台设备的设定语言"，但没说清 `lang` 只能建/改，**设备自己怎么知道**。v1.1 起口径统一为：

| 概念 | 接口 | 谁写 |
|---|---|---|
| 设备身份 | `POST /v1/devices`（bootstrapToken） | 配网工具 |
| 设备语言 | `PATCH /client/v1/devices/{id}`（clientToken） | App / 小程序 |
| 设备读语言 | `POST /v1/device/config`（Device-Key） | **设备自己** |

三者不要混用：**Device-Key 只能调设备接口，不能改语言**（试过，401）。
