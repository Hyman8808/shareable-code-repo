# 词典接口实测报告（重要：与官方文档不一致）

> 测试时间：2026-10-20
> 测试方式：Python 复刻协议 → 直连 `ws://ws-api.turingapi.com/api/v2` 实测
> 结论：**官方文档描述的 AES 加密不可用；明文可直接查通；Secret 无需使用**

---

## 一、核心结论

| # | 节点 | 官方文档 | **实测结果** |
|---|---|---|---|
| 1 | data 字段加密 | 必须 AES/CBC/PKCS5 + Base64，密钥 = md5(apikey+secret+ts)[:16] | ❌ **恒返回 `4008 数据内容格式错误`**（用正确密钥也一样）；反之**明文 data 查询成功** |
| 2 | 是否需要 Secret | 加密必须用 | ✅ **完全不需要** |
| 3 | 请求次数 | 一次请求一次响应 | ❌ **一连接一次请求**，服务端连发三帧：`210` → `220` → `200`(含结果) |
| 4 | 关闭时机 | 收到 done=true | ✅ 正确，但**必须等 done=true**，收到第一帧（210）就关会拿不到结果 |
| 5 | deviceId | 16 位字母数字 | ✅ 必须 16 位，不足会返回 4008 |

### 关键实验记录

| 实验 | 结果 |
|---|---|
| 仅加密（正确密钥） | `4008 数据内容格式错误` |
| 仅加密（错误密钥） | `4008 数据内容格式错误` ← 与正确密钥同码，说明服务端压根没在解我们的密文 |
| 仅明文 data | ✅ `210` → `220` → `200 success` |
| 明文初始化 + 紧随加密请求 | ✅ 成功（说明加密并非拦路条件） |
| 加密两次 | 连接被服务端 1000 关闭 |

## 二、正确请求体（最小可用）

```json
{
  "key": "<DEVICE_API_KEY>",
  "timestamp": "1776643200000",
  "data": {
    "deviceId": "thumbcard0000001",
    "requestType": [1],
    "nlpRequest": {
      "content": [{ "data": "Carton" }],
      "clientInfo": {
        "appState": { "code": 1000633, "operateState": 1101 },
        "robotSkill": {
          "1000633": {
            "dicts": ["cn_char", "cn_idiom", "cn_word_person", "cn_word", "en_word"]
          }
        }
      }
    }
  }
}
```

> `data` 传**字符串化的 JSON**（不是对象），实测字符串与对象均可，App 内用字符串。

## 三、响应序列

```
第 1 帧  {"code":210, "message":"参数初始化成功", "done":false}
第 2 帧  {"code":220, "message":"参数上传完成，正在请求nlp/tts", "done":false}
第 3 帧  {"code":200, "message":"success", "done":true,
          "nlpResponse":{"intent":{"parameters":{"result":{"dict":"en_word","info":{...}}}}}}
```

## 四、实测返回样例

### 英文单词（en_word）— 信息最全
查询 `Carton`：

| 字段 | 值 |
|---|---|
| `dict` | `en_word` |
| `info.word` | `carton` |
| `info.phoneticUs` / `phoneticEn` | `ˈkɑːtn` |
| `info.explanations` | `[{"pos":"n","meaning":"纸板箱；纸板盒"}]` |
| `info.wordAudio` | `http://book-iot-cdn.turingos.cn/...mp3` |
| 其他可用字段 | `examples`（例句）、`synonyms`/`antonyms`、`nounPlurals`、`preterit`、`pastParticiple`、`presentParticiple`、`comparativeDegree`、`superlativeDegree`、`vocabularyGroup`（搭配）、`explanationEn` |

查询 `hello`：`explanations` 返回 `int 喂；你好` + `n (表示问候时的叫声)`。

### 汉字（cn_char）
查询 `和`：主要信息在 `polyphone[]` 数组里（`pinyin`、`explanations`、`combineWords`、`audio`），
另有 `radicalsText`（口字旁）、`structure`（左右结构）、`strokesNum`（8）、`translations`、`synonyms`、`antonyms`。

### 中文双字词（实测落到 others）
查询 `纸箱`：`dict = others`，`info = {"word":"纸箱","translation":"..."}`。
→ **说明中文名词不一定命中 cn_word，可能只拿到翻译**。App 已有降级处理（显示「翻译」）。

## 五、对 App 实现的影响

| 项 | 处理 |
|---|---|
| Secret | **已从 `build.gradle` 移除**，dex 中已确认不含该字符串（`y293...` 查无） |
| 加密代码 | 保留 `DictRequest.encryptWithSecret()` 作为备用，注释标明「当前服务端不接受」 |
| 查询顺序 | 英文名优先（信息最全）→ 中文名兜底 |
| 超时 | 8s；轮询最多 6 帧 |
| 失败降级 | 词典只是增强，失败只显示「暂时没查到」+ 重试按钮，不影响卡片主内容 |

## 六、给你的提醒

1. **Secret 不用再担心泄露**——这个接口根本不需要它。你在群里贴过的 Secret 建议仍然换一个，
   因为别处（如其他图灵接口）可能仍需。
2. 如果后续图灵修好了加密校验，我们会收到 4008，此时按 `DictRequest` 注释恢复加密分支即可，
   但**不要把 Secret 写回 APK**，应改由自家云端接口代理签名。
3. `ws://` 是明文传输，apikey 在请求体里可被抓包看到。若后续上线要过安全审计，
   建议改为自家云端转发（App → 图灵后端 → ws-api），这也是你们原计划的方向。
