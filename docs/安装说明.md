## 二、版本演进与问题修复

### v2.11.6 — 语言真正写进云端（2026-10-28）

**修的是「选了语言但不生效」这个核心问题。** 上一版把 10 档语言做全了，但只写进手机本地：云端不知道用户选了什么，拍照时仍按默认中文出名称。用户看到的现象是「设置里明明选了日语，拍出来还是中文」，而且不报任何错。

| 环节 | v2.11.5 | v2.11.6 |
|---|---|---|
| 选语言后 | 只写本地 SharedPreferences | 本地 + **上报云端 `/api/device/lang`** |
| 云端依据 | 无（恒按 `zh` 出名称） | 按 `deviceId` 查设定语言，拍摄时固化进记录 |
| 结果 | 显示「日本語」但卡片是中文 | 之后拍的照片名称/发音为该语言 |
| 失败处理 | 无 | 自动留 pending，进语言页 / 配网成功 / App 启动时补报 |

**写在代码里的三条边界**（`DeviceLangSync.kt`）：

1. **`none` 必须映射成 `en`** —— 云端白名单是 `zh/zh-Hant/en/ja/ko/es/fr/de/ru/ar`，**没有 `none`**。直接上报会拿 `40000 lang参数错误`。
2. **多设备逐台上报** —— 云端语言按 `deviceId` 存。只报「当前设备」会出现「这台改了、换一台又不行」，而语言页本身没有「当前设备」概念。
3. **参数放 query，不能放 JSON body** —— 服务端不解析 POST body，放 body 会返回 `4005 apikey信息错误`（看起来像密钥错，实际只是位置错）。

**另外改了两处会误导的表达**：语言切换的 Toast 不再说「译名服务接入中，当前显示中文原词」（云端 10-28 已上线，这句会让用户以为功能没做）；小程序同步改用同一个口径。

**验收方法**（真机，1 分钟）：

1. 设置 → 物品名称语言 → 选「日本語」→ 看到「已切换为日语」
2. 用相机拍一张新照片 → 同步后该卡名称应为日文
3. 换一台绑过同一 `deviceId` 的手机（或重装后重新配网）→ 拍新照片，仍是日文（说明语言存在云端而非本地）

⚠️ **历史卡片不跟随语言**：译名在拍摄那一刻就固化了，切语言只影响之后拍的照片。这是既定产品口径，不是本版的缺陷。

⚠️ **阿语能显示、不能朗读**：CosyVoice 通道语种是 zh/en/ja/ko/yue，不含 `ar`，点朗读会回落到英文音频。

### v2.11.5 — 界面语言 10 档 + 本地化朗读（2026-10-28）

上一版界面语言只有 4 档（简/繁/英/阿），名称语言 10 项。用户选了日语、韩语或任一欧洲语言，**界面仍是中文** —— 因为那 6 种语言在 App 里根本不存在。本版补齐。

| 项 | v2.11.4 | v2.11.5 |
|---|---|---|
| 界面语言 | 4 档（简/繁/英/阿） | **10 档**（+ 日/韩/西/法/德/俄） |
| 名称语言 | 10 项 | 10 项（不变） |
| 语言选择弹窗 | 4 行写死在 XML 里 | 按 `UiLanguage.ALL` 动态生成，加语言不用改布局 |
| 详情页首个发音按钮 | 恒为中文 | 设定语言有音频时播**该语言**，文案随语言变（如「日本語で再生」） |
| 数据库 | Room v3 | Room **v4**（+`tts_localized_url`），显式迁移 |
| 译名进缓存 | 🔴 被 `langCode != null` 挡住，选了外语仍显示中文 | 无条件写缓存 |

**三条要讲清的行为变化：**

1. **`lang` 请求参数作废了**。实测 `/api/record/list?lang=en` 与不带参数返回完全一致 —— 云端改成「按 `deviceId` 命中你设定的语言，在**拍摄那一刻**写进记录」。所以切语言不影响老卡片，只有切完再拍的才按新语言。这与之前"历史卡不跟随语言"的规则一致，只是原因变了。
2. **阿语能显示、但还不能读**。TTS 通道（CosyVoice）支持的语种是 zh/en/ja/ko/yue，**不含 ar**。阿语界面、RTL 镜像、译名全部正常，点朗读会回落到英文音频。这一条需要拍板：降级播英文，还是换引擎。
3. **安装是覆盖升级，不用重新配网**。DB 迁移 `MIGRATION_3_4` 是显式的，没有用 `fallbackToDestructiveMigration`——后者会把配对过的设备一起清掉。

> 详细核实过程（含 `grep` 证据与复验命令）见 `docs/多语言10档与App最新接口对齐_2026-10-28.md`。

**本版不含**：`thumbcamera-api` 新栈相关代码。App 与小程序都只走 `nglearn.turingapi.com`，全仓 `grep thumbcamera` 为 0 命中。

### v2.11.4 — 配网健壮性（对应客户 2026-10-27 的 5 条反馈）

客户测的是 v2.11.2（vc47）。其中 3 条是 App 缺陷，本版已修；另外 2 条在云端，需研发处理。
完整分析见 `docs/客户问题反馈_分析与修复_2026-10-27.md`。

| 客户反馈 | 根因 | 本版处理 |
|---|---|---|
| 设备报 10 个、App 只显示 8 个 | ①App 按 **SSID** 去重，同名热点被吞 ②TLV 解码用 Map，一条消息里多条 `0x88` 只留最后一条 | 改为按 `0x88` 的**序号**入表 + 保留重复 TLV；界面明写「设备上报 N 条，其中 M 条同名已合并」 |
| 连到第 7 次必断连 | 远程断连时**只置标志不 `close()` GATT**，每轮漏一个 client，W800 只吃 1 条链路 | 断连即 close、连前先 close 旧链路；写线程识别「断连放行」不再当成功 |
| 等列表 6s 就亮手动兜底 | App **从未自动重发 `0x0E`**（协议 §4.5.7 要求 2 次） | 15s/轮 × 3 轮自动重试；兜底提示挪到 9s 且文案改为「还在等」 |

| 语言相关字段不下发 / 第二包晚 4s | 云端未实现 / 异步生成 | 非 App 侧，转研发（见报告第 4、5 节） |

### v2.11.3 — 阿拉伯语（界面 4 语 / 名称 10 语）+ RTL 镜像

客户问「测试包里有没有阿语」。查证结论：**此前完全没有**——
`values-ar` 里那 105 条是 Material 库自带的（`password_toggle_content_description` 这类），
自有 437 条文案一条阿语都没有。本版补齐。

#### 1. 界面语言从 3 档扩到 4 档

「我的 › 界面语言」新增 **العربية**：

| 档位 | locale | 资源目录 |
|---|---|---|
| 简体中文（默认） | `zh-CN` | `values/` |
| 繁體中文 | `zh-TW` | `values-zh-rTW/` |
| English | `en` | `values-en/` |
| **العربية** | `ar` | **`values-ar/`（新增）** |

阿语 437 条文案全量翻译，**逐键对齐**：4 份 `strings.xml` 键名集合完全一致（437 条），
占位符（`%1$s` / `%2$d`）一个不差、一处 `\n` 不丢。少一个键在阿语界面会静默回落中文，
所以每次改文案都必须四语同改。

#### 2. 物品名称语言从 9 项扩到 10 项

「我的 › 物品名称语言」与「设备语言」两处同时出现 **العربية**（`ar`）。
选它之后：名称随下一次同步按 `lang=ar` 向云端取 `name_localized`，
拿不到译名时**回退显示中文原词**（沿用既有策略，绝不伪造译名）。

> 🔴 **交付边界**：App 侧已打通，但「阿语译名真正出得来」依赖两件外部事项——
> ① 云端 `name_localized` 的 `ar` 通道要开（当前正式版 V2.1 白名单需研发确认）；
> ② 固件 `0x10 ITEM_LANG` 要有 `ar` 对应的提示语资源（否则设备端仍是英文）。
> 这两项不在 App 交付范围内，App 已按协议原样下发，不需要再改版本。

#### 3. RTL 镜像适配（阿语不是「翻译完就行」）

阿语从右往左读，Android 会按 locale 自动镜像整个布局。这次逐项核过：

| 检查项 | 结论 |
|---|---|
| `android:supportsRtl` | Manifest 早已是 `true`，无需改 |
| 布局物理方向属性（`layout_marginLeft` / `layout_toRightOf` / `paddingLeft` …） | **0 处**，全部用的 `Start/End`，自动镜像 |
| 方向性图标 | `ic_back` / `ic_chevron_right` / `ic_chevron_right_16` 补 `android:autoMirrored="true"`，否则阿语下箭头指反 |
| 文本内方向符号 | `‹ ›` 阿语下改写为 `‹`、`→` 改写为 `←`；`common_back` 去掉箭头只留纯文字「رجوع」 |
| 翻页手势 | 自定义触摸实现、未用 ViewPager2 ⇒ 不受 RTL 索引反转影响，无需改 |
| `UiLanguage.normalize()` | 加 `ar` 分支。**这是最容易漏的一处**：漏了会被 `else -> ZH` 静默吞成中文，表现为「设置里显示阿语、界面还是中文」且不报任何错 |
| 输入框（SSID / 密码） | 保持系统默认：RTL 下右对齐，符合阿语书写习惯，不强行 LTR |

### v2.11.2 — 配网不用手打网络名 / 相册找回「看得见为什么没捞回来」

#### 1. 手输 SSID 自动填「手机当前连着的 WiFi」

固件普遍还没实现 `0x0E` 扫列表，客户只能走手输那条路。但让客户手打 SSID 本身就容易失败：
名称里有中文、空格、大小写，打错一个字，最后表现成**「密码错误」**，根本查不到真因。

现在点「手输 SSID」会把这台手机正连着的网络名填进去，客户确认或改一下即可。

| 情况 | 行为 |
|---|---|
| 读到 · 2.4G | 预填名称，光标直接落在密码框 |
| 读到 · 5G | 预填，并显式警告「相机只支持 2.4G」，带出频率 |
| 读不到（没授权 / 没连网 / 系统不给） | 输入框留空，提示手动填写 —— **与 v2.11.1 完全一致，不阻断流程** |

> 🔴 **为什么必须判 5G**：相机只支持 2.4G。平板实测连的是 `tuling / 5220MHz`，
> 如果闷头预填，客户点一下发送、等 50 秒超时，最后拿到的是误导性结论。
> 这个警告不是锦上添花，是防止「我们帮客户预填了一个必定失败的答案」。

读 SSID 需要权限（Android 13+ 是「附近的设备」，更早是「位置信息」），**并且系统定位开关要打开**。
两者任缺其一，系统就返回 `<unknown ssid>`，这是 Android 10 以上的平台限制，不是 App 的问题。

#### 2. 相册找回：修掉「相册里明明有、却说没找到」

🔴 **真 bug**：约定「同一张卡 + 同一种风格只捞一份」的占位动作，原来放在了**所有校验之前**。
后果是：相册里同一张卡同一风格存过多份时，**先被扫到的那份**（可能是截图、可能是转过一手的压缩图，
尺寸不够被 `TOO_SMALL` 挡掉）已经把占位占了，**后面那份真正的全尺寸原图会被当成「重复」直接丢弃**。
表现正是用户反馈的那句话：相册里那张图还在，恢复结果却说没有。

修法：占位挪到「本地已有 → 尺寸校验」全部通过之后，只有**真正要收进结果**的那一份才占位。

#### 3. 恢复结果现在会逐张说明原因

原来只说「跳过 1 张 · 尺寸不足」，这种汇总帮不到现场 —— 分不清是图存小了、库里没有这张卡、
还是本地本来就有。现在直接列出**每张图的文件名 + 具体原因**（最多 8 条）：

| 原因 | 含义与处理 |
|---|---|
| 库里没有这张卡 | 图上的 `cardId` 在本地库里查不到 → **先下拉同步记录再试**（重装后最常见） |
| 尺寸不足（带实际像素） | 存的是缩略图/卡片小图（1080×810 = 87 万像素，门槛是 100 万）→ 从详情页重新存一次 |
| 本地已有 | 当前包的私有目录里已经有这张卡这个风格的图，不必覆盖 |
| 英文名撞了多张卡 | 老图没有标识、只能按英文名猜，命中多张 → 宁可不捞也不乱配 |
| 读不出来 | 权限被收回 / 文件损坏 / 云端占位没落盘 |

### v2.11.1 — 配网兜底：扫描拿不到列表时仍能手输

**为什么必须有这一版**：v2.11.0 把配网页改成了「设备扫 → 用户点选」，同时把原来的手输 SSID 入口**整个删掉了**。这在固件升级到位时是干净的，但现场样机固件若还停在 V1.0 基线（不实现 `0x88`/`0x89` 列表 TLV），设备收到扫描指令既不回列表也不报错，页面就只剩「刷新」一个动作 —— **整台设备永远配不上网**。这是 v2.11.0 自己引入的死角，本版补掉。

| 改动 | 说明 |
|---|---|
| 手动输入入口 | 列表为空 / 扫描失败 / 等待超过 6s，三种情况亮出「手动输入 WiFi」按钮，弹窗填 SSID + 密码（密码留空按开放网络下发） |
| 慢扫描提示 | 6s 没收到列表就把状态文案换成「还没收到热点列表…可以继续等，也可以手动输入」，不再让用户干等 10s 超时 |
| 扫描识别双通道 | 广播包除原 `ORG-ID = 0x070C` 外，新增按设备名前缀 `AIPicCamera` 兜底识别。样机广播字段没按 V1.2 填好时仍能被扫到 |
| 状态收口 | 进入下发（`configBusy`）立即清掉慢扫描计时器，避免配网中把列表区切回空态 |

### v2.11.0 — 配网改为「设备扫 WiFi、用户点选」

**需求**：配网不再让用户手输 SSID，改成「设备扫到哪几个热点就显示哪几个，用户点一个、输密码」。

**为什么必须改**：手输 SSID 有三个必现失败，而且失败原因用户看不出来：

| 手输的问题 | 后果 |
|---|---|
| 用户输了 5G 的 SSID | W800 只支持 2.4G，**必然**配网失败（`0x8A code=3`） |
| 大小写/下划线拼错 | 失败无提示，只能整轮重来 |
| 中文 SSID / 隐藏网络 | 键盘输入体验极差，且隐藏网络本来就输不对 |

改成设备上报之后，**用户只能从「设备真的看得见的热点」里选**，这三类失败从根上消失了。

**协议侧**：新增《WM_W800_BleWiFi 蓝牙配网协议 **V1.2**》——
广播名统一为 `AIPicCamera` + 4 位编号；`0x0E`/`0x8E` 的响应扩展出
`0x88`（`序号|RSSI|AUTH|SSID`，SSID 放行末因此可含逗号）与 `0x89`（`total`/`done`）；
`0x86` 旧格式继续发送，老 App 不受影响。固件必做项合计约 3.5 人天。

**App 侧改动**：

| 文件 | 改动 |
|---|---|
| `BleConstants.kt` | 新增 `0x88`/`0x89` TLV、扫描状态码 `0x08`/`0x09`、扫描超时 15s |
| `model/Results.kt` | 新增 `WifiAp`（含 `signalBars`、`isOpen`）、`WifiScanResult`；`ScannedDevice.supportsWifiListV2` |
| `BleWiFiClient.kt` | 新增 `startWifiScan()`/`cancelWifiScan()`：收 `0x88` 逐条并入、`0x89` 收尾、同 SSID 合并取最强；**补上 `0x10` Ack 回复**（此前从不回） |
| `MessageEncode.kt` | 新增 `encodeRaw()`：`0x10` 的 PAYLOAD 是裸字节不是 TLV，走原 `encode()` 会多 2 字节 |
| `WifiConfigActivity` | 整页重写：进页即连设备 → 协商 → 读凭据 → 请求扫描 → 列表点选 → 加密网络弹密码框 → 下发 |

1. **进页就连接**，不等用户填表。列表是从设备来的，不连上根本拿不到，

### v2.10.0 — 图片大图页左右滑切卡

**需求**：在「记录」或「收藏」里点图片进大图页，也要像单词详情页那样左右滑切上一张/下一张。

**难点在哪儿**：这页不是空白页，中间那个 `ZoomImageView` 自己吃掉了全部触摸
——双指缩放、双击放大、放大后横向拖动都占着横向手势。照抄详情页的
`dispatchTouchEvent` + GestureDetector 会变成两套 detector 解析同一串事件，
而且 Activity 层拿到的 `isZoomed()` 隔了一帧，双击放大后立刻横拖会误切卡。

**做法**：手势出口下沉到 `ZoomImageView` 内部（`onSwipeOut` / `onSwipeBlocked`），
只有在那里 `currentScale` 才与手势是同一时刻的值。

| 规则 | 值 |
|---|---|
| 切卡判据 | 横移 ≥72dp 且横速 ≥320px/s，**或** 横移 ≥25% 屏宽（明确长拖免速度）；横 ≥ 纵×1.2 |
| 放大态 | **一律不切卡**（横拖是平移图片） |
| 放大态想切卡 | 只在「这个方向已经挪不动」时提示一次（含「图比屏窄、根本没有平移空间」） |
| 切卡过渡 | 旧图原地不动；250ms 未就绪才压暗到 0.45；新图解码完成后 α 0.85→1（140ms）|
| 到头 | 图片反向回弹 12dp + 页内提示，**不弹 Toast** |

**为什么不用详情页那套 18% 位移滑入**：这页的图是满屏的，一移就露纯黑边，
看起来像图变小了。所以切卡**完全不移动图片**，方向感交给页码（±6dp 位移）。

**顺手修掉的三件事**

| # | 问题 | 后果 |
|---|---|---|
| 1 | 大图页的 Toast 全部改页内提示条 | 系统 Toast 是浅底深字的方块，压在黑底满屏照片上像补丁，还会盖住底部胶囊 |
| 2 | 加载失败原来只弹一句就结束 | 改成居中「点击重试」占位，且**撤掉旧卡照片** —— 否则「第 4/12 张」下面是第 3 张的图 |
| 3 | 图片加载没有成功/失败回调 | `loadAny()` 加 `onSettled(Boolean)`，成功才淡入（先淡入一张没解码的图＝黑屏） |

**范围**：记录页、收藏页、全部记录页、详情页点大图。**美化页跳预览仍是单张**（那里没有列表上下文）。

**无障碍**：触摸探索开启时，图片两侧出现 48dp 的上一张/下一张按钮（普通用户看不到，
不占照片宽度）；切卡后朗读「第 3 张，共 12 张，高清」。

**文案**：三语（简/繁/英）键数同步 **413**，完全一致。

**背景**：pep#2729 确认了「App 改语言 → 设备下次请求即拿到新语言」这条拉取式链路，多语言不再等 App 侧翻译，改为云端按 `lang` 下发 `name_localized`。

**改了四处**

| # | 改动 | 为什么 |
|---|---|---|
| 1 | `NameLanguage` 由 17 项收敛为 **9 项** | 原来 17 项里 13 项选完只能显示「翻译服务开发中」，等于摆 13 个坏入口。只留能真正出结果的：仅英文 / 简中 / 繁中 / 日 / 韩 / 西 / 法 / 德 / 俄 |

| 3 | 繁体语言码 `zh-TW` → **`zh-Hant`** | 与设备协议统一；`fromCode()` 兼容旧的 `zh-TW`/`zh-HK`，存量用户升级不丢设置 |

### v2.8.0 — 多设备彻底隔离 + 详情页左右滑动切卡

**两个报障 + 一个新需求**：

1. 「我的 → 我的相机」永远写着**未配对**，实际已经绑了两台；
2. 在设备页选第二台，只有那一个页面换了设备，首页/收藏还是第一台；更奇怪的是「设备 2 里能看到设备 1 的记录」；
3. 新需求：单词详情页**左右滑动**切上一张/下一张，范围要比对「从哪进来的」。

#### 修了什么

| # | 问题 | 真因 | 修法 |
|---|---|---|---|
| 1 | 我的相机永远「未配对」 | `tvCameraState` **从来没有任何代码写过**，一直是 XML 里的默认文案 | 新增 `refreshCameraSummary()`：0 台「未配对」/ 1 台「1 台已绑定」/ N 台「N 台已绑定」；多设备时追加当前设备名（≤8 字） |

| 3 | （新功能）切卡 | — | 详情页接收来源列表的 id 顺序，左滑下一张、右滑上一张 |

#### 多设备的三条判定规则

```
我的 → 我的相机 → 点某台  ⟶  设为当前设备（全 App 跟着换）⟶ 退回上一页
                   长按      ⟶  全部记录 / 设为当前 / 重命名 / 解绑
全部记录页顶部胶囊          ⟶  只换本页筛选；点具体设备时顺带设为当前
首页 / 收藏 / 详情          ⟶  一律只看当前设备
```

- **当前设备存的是 deviceId，不是下标**：解绑一台之后下标会整体错位
- 存的那台被解绑 → 自动落回最近绑定的一台，绝不返回 null 让上层去猜
- 「全部设备」是**伪设备 id**（`__all__`），只允许「全部记录」页使用。首页成就统计与收藏列表都不用它 —— 跨设备合并的收藏，「取消收藏」到底改哪台设备上的同一张卡，语义说不清

#### 左右滑动的四个判据

| 判据 | 值 | 为什么 |
|---|---|---|
| 横向位移 | ≥72dp | 过滤上下滚动时的手抖 |
| 横向 vs 纵向 | 横 ≥ 纵 × 1.5 | 斜着滚页面不该翻页 |
| 横向速度 | ≥320px/s | 慢慢横拖是在看内容，不是翻页 |
| 到头 | 回弹 12dp + 一句提示 | 浏览型操作不弹窗，弹窗会打断「继续看」 |

切换范围严格等于**点进来时那一页的列表顺序**：

| 来源 | 左右滑动会经过 |

> 所以直接传 **id 数组**，让「上一张/下一张」与用户看到的列表逐项一致。

### v2.6.1 — 短语拆解「写着 3 个词，卡里只有 2 块砖」彻底修好

> 一句话：**英文名有几个词，页面上就有几块砖；一块都不许少，一块都不会被压没。**
>
> v2.5.1 修的是「拆词阶段悄悄丢词」，这一版修的是**更后面一层**：词已经拆出来了、砖也加进去了，
> 但最后一块在屏幕上被压成了 1px 高 —— 等于没显示。

#### 现象（用户实测）

「绿色盆栽」英文名 `a potted plant` / `green potted plant`，徽章写着 **3 个词**，卡里只有 **2 块砖**，
缺的正是 `plant` —— 而用户点进来最想看的往往就是那个实词。

规律：**只有奇数个词的短语会丢，丢的永远是最后一块**。5 个词会显示 4 块。

#### 真因：占位 View 的 1px 把最后一块砖「钉死」了

两列布局遇到奇数个词时，右侧会补一个透明占位 View，避免最后一块被拉满整行。
旧代码里这个占位的高度写的是 **`1`（1 像素）**，而行内等高逻辑是这样写的：

```kotlin
// 旧代码（v2.5.1）
var h = 0
for (i in 0 until r.childCount) h = maxOf(h, r.getChildAt(i).measuredHeight)  // 占位也算进来了
for (i in 0 until r.childCount) { lp.height = h }                             // 砖也被设成 h
```

于是只要某一帧砖还没量出高度（`grpPhraseBody` 从 `GONE` 转 `VISIBLE` 的同一帧就会这样），
`h = max(砖 0, 占位 1) = 1` → **砖的高度被改成 1px**。下一帧再量，砖还是 1px，`max` 还是 1 ——
自我维持，永久不可见。整行只有一块砖时没有别的砖能拉高它，所以「刚好丢最后一块」。
第一行两块砖互相有伴，`max` 取得到正常高度，所以看起来只有后面那块没了。

#### 改了什么

| # | 改动 | 说明 |
|---|---|---|
| 1 | 占位 View 高度 `1` → `0`，并打上 tag | 等高计算**明确跳过**它，它只负责撑列宽 |
| 2 | 等高方式从「改 `layoutParams.height`」改为「`minimumHeight`」 | 只抬不压：测量异常时砖顶多变矮一点，绝不会被压成一条线 |
| 3 | 等高加门槛：行内最大高度 < 96dp 就整行跳过 | 宁可两列高度参差 1–2 行，也绝不让砖消失 |
| 4 | **砖数以拆词结果为准**，查词典只负责填内容 | 查词失败 / 结果短了 → 自动补一块「暂未收录」的砖，照样出砖 |
| 5 | 去掉 `distinctBy`（同词只留一块） | `plant / Plant` 是两块砖，序号能区分；去重等于替用户丢词 |
| 6 | 去掉「最多 6 个词」截断 | 上限只约束**并发查词典**（8 个），超出的词照样出砖，只是标「暂未收录」 |
| 7 | 三处日志 | `phrase split: ... n=3` / `phrase rendered: n=3 drawn=3` / 徽章写实际砖数 |

#### 现在的规则（写进代码注释，后续改动不得违反）

- `PhraseBreaker.split()` 返回几个词 → 界面必须画几块砖，**这是唯一真源**
- 任何「悄悄少一个」的过滤（去重、截断、白名单、查询上限）都不允许影响砖数
- 冠词 `a / an / the` **照常出砖**，只在底部「直译」条里剔除
- 词砖高度只许 `minimumHeight` 抬高，**不许**用 `layoutParams.height` 往下压

### v2.6.0 — 从相册找回已生成的高清图（AI 版专有）

> 一句话：**生成一张要 60–110 秒、扣一张额度；重装 / 清数据 / 换机后本地那份没了，相册里那份还在 —— 这个功能把它捞回来，不调模型、不扣额度。**

#### 先回答「相册里的图到底有没有标识」

| 这批图 | 标识 | 能不能精确认回 |
|---|---|---|
| v2.6.0 之后存的 | EXIF + 文件名双写 | **能**：cardId 写在字节与文件名里，改名、挪文件夹都不断 |
| v2.6.0 之前存的 | 只有英文名 | **只能猜**：按英文名匹配卡片；名字命重时直接放弃，不瞎配 |

老版本存图只拼了「英文名_风格_时间戳8位」，既没写 EXIF 也没放 cardId。时间戳那 8 位**不能当 id 反推** —— 按它猜会给每张老图安上一个假 id，比认不出更糟。

#### 标识长什么样

- EXIF `ImageDescription`：`ThumbCard|v=1|id=10037|style=hd`
- EXIF `UserComment`：同上（两个字段双写：任一处被图库同步洗掉，另一处还能救）
- EXIF `Software`：`ThumbCard`
- 文件名：`Iced_Drink_高清_TC10037_20261022.jpg`

**锚点为什么是 cardId**：卡片主键是**云端记录 id**，不是本地自增序号。所以重装后重新配网绑定、重新拉同一批记录，同一张卡的 id 完全一致。换成任何本地编号，重装后就全对不上了。

#### 三级匹配（从可信到不可信）

| 级别 | 判据 | 说明 |
|---|---|---|
| 精确 · EXIF | 见上（`ThumbCard` 开头） | 改名、移动文件夹都不受影响 |
| 精确 · 文件名 | `…_TC{cardId}_{日期}.jpg` | EXIF 被修图 App 洗掉时的备份通道 |
| 猜 · 英文名 | 文件名以卡片英文名开头 | 仅老图；命中多张卡时放弃，在结果里单独告知张数 |

#### 没恢复的，都去哪了

| 原因 | 判据 |
|---|---|
| 已在本地 | 同卡同风格的文件已存在 → 不覆盖（本地那份可能更好） |
| 找不到卡片 | cardId 在本地库里不存在（多半还没同步记录） |
| 名称重复 | 英文名命中了多张卡，宁可少捞也不错配 |
| 尺寸不足 | 宽 < 1080 或像素 < 100 万 —— 挡掉 4:3 的「卡片用图」与截图 |
| 读不出 | 权限被收回、文件损坏、云端占位没落盘 |

像素门槛卡 100 万的理由：全尺寸 2048×1024 ≈ 210 万像素，卡片用图 1080×810 ≈ 87 万像素。卡在中间，卡片用图被干净挡掉 —— 它是 4:3 裁过的，当高清图用会缺两边、放大还发虚。

#### 入口与保护

| 项 | 处理 |
|---|---|
| 入口位置 | 我的 › 其他 › 从相册找回高清图（右侧常驻「不消耗张数」） |
| 可见范围 | **仅 AI 版**；主线该行 `GONE`（主线不生成 AI 图，无所谓找回） |
| 正在批量生成 | 拦下并提示「等这一批结束」—— 两条路径同时写同一张卡的 aiStyle 会互相覆盖 |

| EXIF 写失败 | 退回原字节照常存图 —— 宁可图认不回来，也不能因为写标识把图弄坏 |

### v2.5.1 — 短语拆解「三个词只出两块砖」修复

> 一句话：**拆词时有一条「白名单」在静默丢词，而徽章上的数字用的是丢之前的数量 —— 现在改成只要还有英文字母就出砖，徽章也改成按真正的砖数写。**

#### 现象

「绿色盆栽」这类英文名是三个词（如 `a potted plant` / `3D glasses`），详情页「短语拆解」卡里只出现两块词砖，看起来像拆漏了一个词。

#### 根因（两条，叠在一起才出现）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `PhraseBreaker.split()` | 词必须**整体匹配** `[A-Za-z][A-Za-z\-']*` 才留下，否则静默丢弃：`a/an/the` 被当冠词删、`3D` 首字符是数字被删、`T-shirt’s` 的弯引号不认、`green␠potted`（NBSP U+00A0）粘成一坨后一起被删、带 `/ \| ·` 的 token 整词被删 |
| 2 | `CardDetailActivity.loadPhraseBreakdown()` | 徽章数字用 `split()` 的结果，词砖来自查词结果 —— 两处不同源，一旦过滤口径变了就对不上，而且**不报错、不写日志** |

补充：`split()` 的注释写着「数字开头的（3D）也保留」，但正则要求首字符必须是字母 —— 注释与实现本来就是矛盾的，属实现亏欠。

#### 改法

| 项 | 现在 |
|---|---|
| 拆词策略 | 白名单 → **黑名单**：只要有英文字母就出砖；纯标点/纯符号才丢 |
| 空白字符 | `[\s\u00A0\u2007\u202F]+`（补上 NBSP、FIGURE SPACE、NARROW NBSP） |
| 首尾标点 | 增补弯引号、竖线、间隔号等符号；弯引号统一成直引号后再查词 |
| 冠词 | **照常出砖**（数量必须与英文名词数一致），只在「直译条」里剔除 —— 不会再出现「a potted plant 只拆两根」 |
| 上限 | 4 → **6 个词**；超出会截断并打 warning（不静默） |
| 徽章 | 渲染完成后按**实际砖数**再写一次，保证「徽章写的数 = 屏幕上的砖数」 |
| 等高 | 行内按最高砖强行对齐（`addOnLayoutChangeListener`，只抬不压）—— 兜住「最后一块孤砖被量成 0 高」这类测量链问题 |
| 日志 | `adb logcat -s PhraseBreaker CardDetail` 可看到 `split name="…" -> [词列表]` 与 `phrase rendered: … -> […]` |

1. 「绿色盆栽」详情页：徽章数与词砖数**一致**（3 个词 = 3 块砖，最后一块单独占左半格，右侧留白）
2. 点第三块砖：弹出该词音标 + 释义
3. 「直译」条里**不出现冠词**（`a potted plant` → 「盆栽的 · 植物 → 盆栽」，不是「一 · 盆栽的 · 植物」）
4. 单词卡（apple）：短语拆解区仍然不出现

### v2.5.0 — 高清图能放大了；出图比例跟原图走；多比例适配

> 一句话：**之前「双指缩放」只写在提示文案里，代码根本没生效；顺便把「出图必须跟拍摄比例一致」这条从「靠模型自觉」改成「我们自己算」。**

#### 1. 高清图放不大（真 bug，不是没做）

**症状**：点卡片封面进看图页，提示写着「双指缩放 · 双击放大」，
但两根手指怎么捏都没反应、双击也不动。能点、能滑，就是不大。

**根因**：`ZoomImageView` 的 `scaleType` 写的是 `FIT_CENTER`。
ImageView 的 `configureBounds()` 里有一条硬逻辑：

```
if (ScaleType.MATRIX == mScaleType) 用 setImageMatrix 传进来的矩阵
else                                 用 scaleType 自己算的矩阵
```

所以只要 `scaleType` 不是 `MATRIX`，我们设进去的缩放矩阵**下一帧就被覆盖**。
手势回调照常执行、`currentScale` 照常在变、日志一切正常，画面纹丝不动。

**修法**：`scaleType` 改成 `MATRIX`，把 fit-center 的基准矩阵也自己算（`baseMatrix`），
全程只走 MATRIX 一条路。顺带三件事：

| 改动 | 为什么 |
|---|---|
| 缩放上限 5×，双击 2.5× | 2K 图 FIT 显示约 0.5×，5× 才能看到像素级细节 |
| 看图页解码原尺寸（`size(ORIGINAL)`） | 否则 Coil 按控件尺寸降采样，放大 5× 看到的是被拉伸的 1080 像素，会得出「高清图没用」的错误结论 |
| 返回键先复位再退出 | 放大看局部后，退出意图通常是「先缩回看全图」 |

顺带修掉的：看图页关掉 crossfade —— 淡入过程 drawable 会换两次、缩放矩阵被复位两次，
手快的人会在 100ms 内看到画面回弹。

#### 2. 出图比例：不再交给模型猜

以前传 `size = "2K"`。档位只约束「总像素量级」，**比例是模型自己看着办的**。
实测它确实跟着输入图走，但那是模型行为、不是接口契约 —— 换模型、换版本、
或者干脆换一个客户的相机比例，就可能出一张比例不对的图。

现在改成：**读原图宽高比 → 算出确切像素 → 传 `2048x1536` 这样的具体尺寸**
（`AiImageSize`，长边 2048、对齐 8、总像素夹在方舟允许的 921600–4624220 内）。

| 客户相机比例 | 传给方舟的 size | 全尺寸图（存相册/放大看） |
|---|---|---|
| 4:3 | `2048x1536` | 一比一还原，**卡片用图零裁切** |
| 16:9 | `2048x1152` | 一比一还原 |
| 1:1 | `2048x2048` | 一比一还原 |
| 2:1（当前这批机器） | `2048x1024` | 一比一还原 |
| 3:4 竖拍 | `1536x2048` | 一比一还原 |
| 4:1 长条 | `2048x512` | 一比一还原 |

> 配置项 `ARK_SIZE` 默认 `auto`。填 `2K` / `1K` 之类可以强制回到档位，
> 只用于排查「是不是尺寸参数导致的出图异常」。

#### 3. 一张图两个用途，比例只能保一个，所以拆成两张

这条是给「后续其他客户 4:3 / 16:9 / 1:1」定规矩的：

| | 全尺寸图 | 卡片用图 |
|---|---|---|
| 比例 | **原图比例，一张都不裁** | 卡片框比例 **4:3**，居中裁 |
| 用途 | 看图页、存相册、打印 | 列表/网格/详情页封面 |
| 位置 | `cards/ai/<id>_<style>.jpg` | `cards/ai/<id>_<style>_card.jpg` |

裁切损失（只发生在卡片用图上）：

| 拍摄比例 | 保留画面 | 裁在哪 |
|---|---|---|
| 4:3 | **100%** | 不裁 |
| 16:9 | 75% | 左右各 12.5% |
| 1:1 | 75% | 上下各 12.5% |
| 2:1（当前机器） | 67% | 左右各 16.7% |
| 3:4 竖拍 | 56% | 上下各 22% |

**为什么卡片框不定成 4:3 以外**：客户三种常见比例里，4:3 是唯一能对其中一种做到零损失的；
选 3:2 会让 16:9 好看一点，但让 4:3 的相机白白丢 11%。
真正兜底的是「点开能看完整图 + 能放大」，所以封面整齐优先。

#### 4. UI 侧的多比例适配（改了四处）

| 位置 | 改动 | 原因 |
|---|---|---|
| 详情页图片区 | 固定 `216dp` 高 → **4:3 比例约束** | 原来 216dp 在 375dp 宽屏上是 1.55:1，跟网格卡的 4:3 不是一个比例，同一张图在两处裁得不一样 |
| 美化页预览 | `centerCrop` → **`fitCenter`** | 这页展示的是「生成结果」，用户接下来点「存到相册」拿的是完整图。这里裁了，看到和拿到的就不是同一张 |
| 批量页当前预览 | `centerCrop` → **`fitCenter`** | 同上；一批里混着 4:3 / 16:9 时，裁切会让它们看起来像被随机切过 |
| 网格卡图框 | 保持 4:3，比例值提为 `ImageStore.CARD_ASPECT` | 单一来源。这个常量与两个布局的 `layout_constraintDimensionRatio` 必须同步改，已写在注释里 |

看图页本来就是 `FIT_CENTER`（任意比例完整显示），修好缩放后不用动。

#### 5. 验收点

1. 点任意卡片封面 → 看图页 → **双指放大能进能出、双击能放大能复位、放大后能拖动**（拖动到边界会停住）
2. 放大状态下按返回键 → 先缩回完整显示，再按一次才退出
3. 高清图上双指放到 5× → 像素是实的，不是被拉伸的糊块
4. 生成一张高清图 → 看日志 `ArkImageClient: generate size=2048x1024`（2:1 机器）；存相册后用系统相册看详情，**比例与相机原图一致**
5. 详情页图片区与收藏页网格卡的图，**同一条边裁在同一个位置**（都按 4:3 居中）
6. 竖屏窄手机上，详情页图片不变形、不拉伸

### v2.4.2 — 看图页直接就能「AI 美化」

> 一句话：**把「美化」按钮搬到用户最想点的那一屏 —— 看到原图发虚的那一秒。**

#### 1. 为什么加在这里

原来的路径是：列表点图 → 看原图 → 退出 → 进卡片详情 → 找「AI 美化」。
两步之外，用户已经走了。而相机原图只有 **160×80**，在预览页放大后像素感是很直观的，
「这张能不能清楚点」这个念头就在这一屏产生 —— 转化点应该在这里，而不是藏在详情页。

所以预览页底部多了一个荧光胶囊按钮（这一页是全 App 唯一黑底页，荧光压上去对比度约 12:1）：

| 这张卡的状态 | 按钮文案 | 点进去 |
|---|---|---|
| 一张 AI 图都没有 | **AI 美化这张** | 美化页，默认选中「高清修复」 |
| 已有高清、没有卡通 | **换个风格** | 美化页，默认选中「卡通化」 |
| 已有卡通、没有高清 | **换个风格** | 美化页，默认选中「高清修复」 |
| 两种都有 | **换个风格** | 美化页，默认选中「高清修复」 |

按钮右边跟着一行小字显示剩余额度（「剩 2 张」/「不限」）——
不限额设备（`c8586a630000`）显示「不限」，即使压测几百张也不会在客户面前露出「剩 0 张」。

**「换个风格」不做二选一弹窗**：多一次点击就多一次流失，直接替用户选**还没做过的那档**，进去仍可改。

#### 2. 从美化页回来会自动换图

预览页 `onResume` 会重新对一次账，两种情况都能切过去：

- 生成了**另一档** → 库里 `aiStyle` 变了 → 直接显示新图；
- **重做同一档**（覆盖了原文件）→ `aiStyle` 没变，但文件 `lastModified` 变了 → 也要重绘。

只比 `aiStyle` 会漏掉第二种，用户会觉得「我明明重做了，怎么还是老图」。

另外，这一页也订阅了生成事件：用户不等结果就按返回时，任务还在后台跑，
页面停在可见状态就能收到「这张生成好了」，**图自己换掉**，不用退出去再进来。
正在生成的那一张，按钮会变成「正在生成…」并禁用 —— 否则用户会以为刚才那一下没生效，
再点一次等于重复扣额度。

#### 3. 美化页的一处行为调整

带 `EXTRA_STYLE` 进来（即「换个风格」）时，**不把已有的那档摆成结果**，而是显示原图 + 一行提示
「已有一张「高清」图，选另一种风格再生成一张」。

原因：如果把已有图摆在结果位，用户会以为刚生成的就是它，点「存到相册」存的还是老图 —— 白花钱的错觉比没功能更伤。

#### 4. 建议的验收步骤

1. 任意列表点一张图 → 进预览页 → 底部应有荧光「AI 美化这张」+ 右侧额度小字。
2. 点它 → 美化页，应默认选中「高清修复」→ 生成一张。
3. 返回预览页 → **应自动显示新的高清图**，底部出现「原图 / 高清」胶囊，按钮变成「换个风格」。
4. 点「换个风格」→ 美化页应默认选中「卡通化」，且预览位显示**原图**而不是那张高清图。
5. 生成卡通 → 返回预览页 → 应自动切到卡通图，胶囊变成三个。
6. 对同一张再做一次「高清修复」→ 返回预览页，**图应该是新的**（不是缓存里的老图）。

### v2.4.1 — 修「离开一下就没了」/ 批量入口补齐

> 一句话：**修掉「生成中一离开页面、或者手机待机再回来，就彻底没反应」，并且把批量修图入口从「只有收藏页有」补到「首页和全部记录页都能一步进」。**

#### 1. 修 bug：生成中离开 / 待机回来，页面卡死

现象：点「开始生成」→ 按 Home 键（或锁屏）→ 回来看，**按钮一直禁用、图还是原图**，既没有结果也没有报错；手机待机久一点再回来，甚至不再继续生成。

查下来不是一件事，是**两层原因叠在一起**：

| # | 根因 | 为什么 | 这一版怎么修 |
|---|---|---|---|
| ① | 后台跑完的事件，页面根本收不到 | 页面退到后台时事件订阅被暂停，而这个事件流是「只发一次、不做重放」的——那一刻没人接收就**直接丢弃** | 不再依赖事件：`onResume` 主动做一次**对账** |
| ② | 对账条件被自己的标志位挡死 | 旧代码写的是「只有当前不在生成中，才去补刷」，可事件丢了正说明状态还停在「生成中」→ 条件永远不成立，成了死锁 | 对账**只看事实**：库里有没有 AI 标记、文件在不在、队列里还有没有这张 |

新的对账逻辑（`AiBeautifyActivity.reconcile()`）按三处真相推导界面，四条分支：

| 事实 | 界面 |
|---|---|
| 库里已有 AI 标记且文件在 | 直接显示结果（后台跑完的那张补上） |
| 队列里还有这张，服务也在跑 | 显示「生成中」 |
| 队列里还有这张，但服务已经不在了（被 ROM 杀掉） | **自动接着跑**，并提示「接着上次的进度继续生成…」 |
| 任务没了、也没有结果 | 明确提示「生成被系统中断了，点开始生成再来一次」，不再留一个永久禁用的按钮 |

#### 2. 批量修图入口补齐（这是真正的可用性问题）

原来只有一个入口：**收藏 Tab → 右上角「选择」**。这等于把「批量修图」绑死在了「收藏」上——而批量要处理的是**拍过的照片**，多数人不会先逐张收藏再想修图；收藏为空时，这个能力等于不存在。

这一版把入口补到三处：

| 位置 | 形态 |
|---|---|
| 首页「今天拍的」区块头 | 右侧「批量修图」→ 直接进多选态 |
| 首页「更早的记录」区块头 | 同上（两个区块头互斥出现，保证任何状态下都有） |
| 全部单词记录页 | 顶栏右上「选择」；列表任意一行长按也直接进多选 |
| 收藏页（原有） | 顶栏「选择」/ 长按卡片 |

多选态的交互（与收藏页完全一致，学一次就行）：

- 点「批量修图」→ 进入多选态，底部浮出操作条：**已选 N 张** + **剩余额度** + **高清修复** / **卡通化**
- 任意一行点一下 = 勾选（此时收藏心收起，不会误触）
- 返回键 = **退出多选**，不会退出页面（勾了 8 张一按返回全丢是最恼人的）
- 一条记录都没有时，「选择」按钮直接收起，不留死按钮

#### 3. 建议的验收步骤

1. 进任意一张卡 → AI 美化 → 选「高清修复」→ 点开始 → **立刻按 Home 键**。
2. 等 1–2 分钟 → 回到 App：应看到结果图 + 「生成了 2160×1080」这句，**不再卡在「正在生成…」**。
3. 重复第 1 步，这次改成**锁屏放 5 分钟**：回来应能看到结果；若系统真把服务杀了，应看到「接着上次的进度继续生成…」并自动续跑。
4. 首页「今天拍的」右侧点「批量修图」→ 应直接进多选态、底栏浮出（不用先去收藏）。
5. 勾 3 张 → 高清修复 → 确认弹窗 → 开始 → 按返回 → 通知栏有进度、封面逐张自己变。
6. 多选态下按一次返回键：应只退出多选，页面还在。

### v2.4.0 — 封面真的会换了 / 卡片用图 / 批量化身后台跑

> 一句话：**修掉「AI 图生成了但卡片封面没换」，并且把批量生成从「必须盯着屏幕」改成「丢后台，完成叫你」。**

#### 1. 修 bug：生成高清图不替换卡片封面

用户反馈的现象是「生成完了，封面还是原来那张」。查下来是**三个独立原因叠在一起**，只修一个都还会复现：

| # | 根因 | 为什么会这样 | 这一版怎么修 |
|---|---|---|---|
| ① | Coil 内存缓存命中了旧图 | 本地文件为了省空间关掉了磁盘缓存，而 Coil 对 `File` 的 cache key 带不带 `lastModified` 取决于磁盘缓存策略 —— 一关就只剩**路径**。同名文件被覆盖后，内存里那张旧 bitmap 照样命中 | 显式给 `memoryCacheKey = 路径 + lastModified`（`util/ImageExt.kt`），文件名没变但内容变了就是新 key |
| ② | 生成完列表不会主动刷新 | 列表只在 `onResume` / 切 Tab 才重读数据库。旧流程里任务在批量页前台跑，回来才刷新，所以「看起来还行」；一旦后台跑（本版新能力），封面就会一直不动 | 新增进程内事件 `AiTaskCenter.cardUpdated`，每生成好一张就 `notifyItemChanged` 那一格。首页 / 收藏 / 全部记录三处都订阅 |
| ③ | 写库失败被静默吞掉 | `setAiStyle` 外面包着 `runCatching`，数据库不可用时只更新内存缓存 | 生成后**回读一次**做断言，失败写 logcat（`AiRepository`），下次有据可查 |

> 顺带验证：详情页大图、列表缩略图、收藏网格封面**都走同一个 `loadCardImage()`**，所以一处修好三处一起好。

#### 2. 新增：卡片用图（4:3），和 2K 全尺寸图一起落盘

相机原图 160×80 是 **2:1**，方舟按原图比例出图 → 2K 图也是 2:1（2160×1080）。
而卡片图框是 **4:3**，`centerCrop` 会把左右各切掉 25% —— 主体稍偏就没了（实测「电水壶」的把手被裁掉）。

所以一张卡现在存**两张**：

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `cards/ai/<id>_hd.jpg` | 2160×1080，约 1.5MB | 看大图、存相册（用户花钱买的就是它） |
| `cards/ai/<id>_hd_card.jpg` | **1080×810（4:3 居中裁切）**，约 200–350KB | 列表 / 收藏 / 详情页封面 |

卡片用图在**落盘时**就裁好缩好，好处不止是不被裁：
- 列表不用再解码一张 2K 图（2160×1080 解一次约 9MB 内存），滚动更稳；
- 旧版本（v2.3.0 之前）生成的图没有 `_card` 后缀那张，`displayFile()` 会自动退回全尺寸，**不会显示成「没生成过」**。

#### 3. 批量生成改为「后台跑 + 完成通知 + 被杀能续跑」

v2.3.0 的任务挂在 `lifecycleScope` 上，用户一按返回就取消 —— 钱花了图没了。这一版把执行搬进**前台服务**：

**产品逻辑（和产品对齐后的定稿）**

1. 收藏页多选 → 「高清修复」→ 确认弹窗写清四件事：几张、多久、扣多少、**能不能走开**。
2. 点开始 → 进入进度页，页面上常驻一行「可以离开这一页，App 会在后台继续生成，完成后通知你」。
3. 进度页的「返回」= **转后台，不停止任务**；「停止」才是破坏性操作，要二次确认。
4. 通知栏常驻进度（`正在生成 AI 图 3/8` + 当前词 + 进度条）和「停止」按钮。
5. 生成期间用户可以去首页、收藏、我的随便逛，**生成好一张封面就变一张**（第 1 节的 ②）。
6. 全部结束发一条完成通知，点开直达「收藏」Tab。
7. **App 被杀 / 被 ROM 清理**：队列落盘在 SharedPreferences，下次打开 App 弹窗「上次的修复还没做完，还有 N 张」→ 继续 / 稍后再说 / 放弃剩余。已完成的不会重复扣。
8. 额度中途见底：队列**保留**（不清空），提示买完可以继续 —— 和「用户主动停止」区分开。

**技术要点**

| 项 | 做法 | 为什么 |
|---|---|---|
| 执行者 | `AiTaskService`（`foregroundServiceType="dataSync"`） | 十几分钟的任务只有前台服务扛得住；`dataSync` 是 API 34+ 必须声明的细分类型 |
| 状态 | `AiTaskCenter`（进程内 `StateFlow` + `SharedFlow`） | 页面、通知读同一份进度；单张/批量共用一条代码路径（单张 = 长度 1 的队列） |
| 落盘 | `AiTaskStore`（SP + JSON，存**剩余** id） | 存「还没做的」而不是游标：剩下的就是要跑的，续跑不用额外逻辑 |
| 唤醒 | `PARTIAL_WAKE_LOCK`，60 分钟上限，跑完立刻释放 | 锁屏后 Doze 掐网络，90 秒的请求很容易超时 |
| 停止语义 | 只置标志，**当前这张跑完再停** | 硬切协程会把已经花掉的钱扔了 |
| 通知权限 | Android 13+ 开跑前请求；拒绝也照跑 | 通知是「方便」，不是「前提」 |

⚠️ **华为/鸿蒙**：ROM 仍可能强杀进程。强杀后靠第 7 条续跑；如果连 App 都不给重开，那就只能等下次打开 App 时提示继续。

#### 4. 建议的验收步骤（真机）

1. 收藏页选 **3 张** → 高清修复 → 确认弹窗里应能看到「可以离开这一页」这句。

### v2.0.3 — 收藏页改回卡片流

#### 为什么要改

v2.0 把三个列表统一成了「词典行」（88dp 一行、透明底、靠发丝线分隔）。这对**首页**是对的 —— 刚拍完扫一眼，要的是「有几张、都是啥」，行式一屏能看 3 行多。

但**收藏**是另一种场景：回头看自己挑了哪些卡，图是主角，行式那个 64dp 缩略图太小了。所以收藏页单独回到卡片流。

#### 改了什么

**① 2 列卡片，图片 4:3 贴顶**

卡片宽 154dp（360 屏），图按宽度算高度、不写死 dp，任何屏宽都不变形。用 4:3 而不是 1:1 或 16:9：相机就是 4:3 出片，另外两个比例都会裁掉原图（1:1 裁左右、16:9 裁上下 25%），物品可能被切掉。

**② 卡片三行文字，比旧版多一行读音**

| 行 | 内容 | 字号 / 字体 | 颜色 |
|---|---|---|---|
| 1 | 英文词头 | 19sp 衬线 | 墨 `#1A1917` |
| 2 | 音标，没有则拼音 | 14sp 衬线 | 灰 `#6E695E` |
| 3 | 中文释义 | 15sp 无衬线 | 墨 `#1A1917` |

第二行是这版的关键：**有读音的卡才像词典卡，没有就只是带标签的照片**。

音标**只读本地词典缓存，不发网络请求** —— 你打开过这个词的详情页，卡片上就有音标；没打开过就退到拼音。两者都没有时那一行**留白而不是收掉**，否则同一行两张卡高度不同、网格会参差。

（读音用灰色不是墨色：154dp 宽的卡上，同色同族的 14sp 会被读成「第二行正文」而不是读音。）

**③ 收藏心浮在图片右上角**

荧光圆底 + 墨色实心，28dp 视觉 / 44dp 热区。

**取消收藏只走这颗心，卡片本身不做长按** —— 首页长按是「收藏」（加法），收藏页长按是「取消收藏」（减法），大面积卡片上长按太容易误触，减法操作必须目标明确。

**④ 间距**

RecyclerView 左右 padding 14dp + 卡片 6dp 外边距 = 第一列距屏边 20dp，与标题缩进对齐；列间距 12dp。顶部多留 10dp，让第一行卡片的阴影不被列表边缘切平。

|---|---|---|
| 首页 | 词典行 88dp | 3 整行 + 第 4 行露 28% |

### v2.0.2 — 重做应用图标

#### 为什么改

v1.x 的图标是**白色相机 + 亮蓝镜头（`#4C6FFF`）**，属于上一代品牌色，和 v2.0「墨标」的墨蓝（`#172742`）+ 暖纸（`#F4F2EC`）+ 荧光（`#D9F24F`）完全脱节 —— 桌面上点开是墨标界面、退出来是亮蓝图标，像两个 App。而且白相机剪影与同屏所有相机 App 无法区分。

#### 改了什么

**① 造型：从「相机」换成「卡片」**

墨蓝底 + 暖白卡片 + 顶部荧光标记条 + 两行词条（长行墨蓝 = 英文词头，短行灰 = 中文释义）。它是 App 内**词典行**的缩影，语义指向「单词卡」而不是「又一个相机」—— 通用相机剪影反而没有辨识度。

第二行用 `#6E695E`（`text_tertiary`）而不是墨蓝，是照 App 内「英文是主角、中文是副行」的层级来的；两行同色缩到 48dp 会糊成一片。

**② 补齐三种图标形态**

| 形态 | 文件 | 覆盖系统 |
|---|---|---|
| 自适应图标（圆形 / 圆角方形 / 水滴，随厂商遮罩） | `mipmap-anydpi-v26/ic_launcher.xml` | Android 8.0+ |
| 圆形图标 `roundIcon` | `mipmap-anydpi-v26/ic_launcher_round.xml` | Android 7.1+ 圆形桌面 |
| 主题图标 `monochrome` | `mipmap-anydpi-v33/ic_launcher.xml` | Android 13+ 跟随壁纸取色 |
| 旧式图标回退 | `mipmap-hdpi/ic_launcher.xml` | Android 6–7 |

v2.0.1 之前只有第一种，且 `AndroidManifest` 里没声明 `android:roundIcon`。

**③ 主题图标是补齐而不是照搬**

开启主题图标的用户，系统会把整层染成单一壁纸色。所以 `ic_launcher_monochrome.xml` 只表达**结构**：卡片线框 + 头部区隔线 + 两行词条，与彩色版一一对应。没这层的话，开了主题图标的用户会看到一个白底方块。

#### 安全区（不用担心被厂商遮罩切角）

自适应图标 108×108 画布，真正的可见区是中心 72×72，最保守的是 ⌀66 安全圆。本图标卡片 **44×50**，最远点（卡片圆角处）距圆心 **33.3dp** —— 略超安全圆半径 33，但远在 72×72 可见区内（半径 36）。实测圆形、圆角方形两种遮罩下，卡片四角与荧光条均不被切。想直观看：打开 `docs/图标预览.html`。

#### 无业务影响

只动了 `res/drawable/ic_launcher_foreground.xml`、`res/drawable/ic_launcher_monochrome.xml`（新增）、`res/values/ic_launcher_background.xml`、`res/mipmap-*/` 下的 8 个 adaptive/round xml、`AndroidManifest.xml` 加一行 `android:roundIcon`。**Kotlin 业务代码、数据库、界面布局、文案零改动**；Room 三个 `_Impl` 类已核在包内（6 / 15 / 35，与 v2.0.1 一致）。

#### 装法

直接覆盖安装即可（包名、签名、数据库版本都没变）。**换图标后桌面可能仍显示旧图标**，这是 launcher 的图标缓存：

- 多数机型 10–60 秒内自动刷新；
- 没刷新就重启一次手机；
- 仍不刷新：设置里清「桌面 / Launcher」的缓存，或先卸载再装。

### v2.0.1 — 修复「配网成功却提示未绑定」的致命缺陷

> **只修一个 bug，界面与交互与 v2.0.0 完全一致**，没有任何界面逻辑改动。

#### 用户看到的症状

配网成功后进了「全部单词记录」页，但：
1. 页面上**什么操作都做不了**（没有收藏、没有返回按钮能回首页）；
2. 按返回 → 回到「选择设备」界面 → 再返回 → 回到「添加设备」；
3. 回到首页，**显示的还是「未绑定设备」**，等于白配一次网。

#### 真正的根因（不在界面，在包）

v2.0.0 的 APK 里，**Room 自动生成的三个类少了两个**：

| 类 | v1.9.0 | **v2.0.0（坏包）** | v2.0.1 |
|---|---|---|---|
| `AppDatabase_Impl` | ✅ | ✅ | ✅ |
| `BoundDeviceDao_Impl` | ✅ | ❌ **缺失** | ✅ |
| `WordCardDao_Impl` | ✅ | ❌ **缺失** | ✅ |

于是流程变成：
```
配网成功 → 写入绑定记录 → 调用 BoundDeviceDao_Impl（不存在）
        → BindRepository 捕获异常 → 返回 StorageUnavailable
        → 判定「本地存储不可用」
        → 走「临时模式」兜底：不保存绑定，直接跳进临时单词卡列表
        → 首页读不到绑定记录 → 显示「未绑定」
```

也就是说：**不是界面跳转错了，是数据库写不进去，程序被迫走了「临时模式」这条降级路径**。界面上那句「临时模式已加载」的提示一闪而过，用户只会觉得"配完网什么都没发生"。

#### 为什么会少两个类

不是代码问题，是**构建过程被并发搞坏了**：

1. 出包时团队里有多个人同时在跑 Gradle；
2. 中途 `clean` 因为文件被占用而**半途失败**，`app/build` 留下残缺状态；
3. KSP 在 00:57 正常生成了三个 `.java`，javac 也编译出了 `.class`，**但 dex 打包沿用了损坏的增量状态**，只打进了 `AppDatabase_Impl`。

所以「代码是对的、编译也成功、运行却缺类」——这类问题在源码层面完全看不出来。

#### 修法

1. `gradle --stop` 停掉所有守护进程；
2. `gradle clean` **彻底删除** `app/build`（确认目录已不存在，而不是"部分删除"）；
3. `assembleDebug --no-build-cache` 全量重建；
4. **出包后直接从 APK 的 dex 字节里核对三个类名**（不看构建日志，看最终产物）：
   ```
   AppDatabase_Impl      count=6
   BoundDeviceDao_Impl   count=15
   WordCardDao_Impl      count=35
   ```
   三个都在，且数量级与 v1.9.0 一致。

#### 以后怎么防（已写进出包检查项）

> **Room 项目出包必须验 dex 里三个 `_Impl` 类是否存在。** 构建日志 `BUILD SUCCESSFUL` 不代表类打进去了；`clean` 报"部分文件删不掉"时，**不许继续出包**，必须停掉所有构建、彻底删掉 `app/build` 再重来。

#### 升级注意

- 直接覆盖安装即可，**不需要先卸载**（包名、签名、数据库版本都没变，已有绑定记录会保留）。
- 如果之前装过坏的 v2.0.0 并已经在用，升级后**重新配一次网**即可；旧的临时模式没有落库，本来就没有可迁移的数据。

### v1.0.6 — 修复 deviceId 错位

**经 `activatedDevices_0_32.xlsx` 激活清单核对，定位到「配网成功但查不到记录」的真凶：**

| 来源 | deviceId |
|---|---|
| 云端激活清单（权威，第 18 行 / 终端 652103447） | `c8586a6382**22**` |
| App 由 BLE 广播 MAC 推导 | `c8586a6382**23**` ❌ 末位 +1 |

**原因**：BLE 广播地址 ≠ 设备真实 MAC。设备广播时普遍做 +1 偏移（避免被 Android 过滤），
因此 `C8:58:6A:63:82:23` 推导出的是不存在的设备号，云端必然返回空。

**v1.0.6 修复内容：**

| 通道 | 说明 |
|---|---|
| ① 自动候选匹配 | 由广播 MAC 生成候选（-1 / 原值 / +1 / -2），逐个查云端，命中即自动切换 |
| ② 手动修正 | 单词卡页右上角新增「修正设备号」按钮，候选一键填入 / 手动输入 / 保存即校验 |
| ③ 一键恢复 | 修正有误可「恢复为自动识别」 |

优先级：**人工修正值 > 固件上报值 > 广播 MAC 推导值**（固件补上 `0x8D` 的 TLV `0x0B` 后自动生效，App 无需再改）

**⚠️ 注意**：即使修正为正确的 `c8586a630000`，当前云端该设备号下 total 仍为 0。
33 台设备中只有 `c8586a630100` 有 1 条记录 → **设备端上传链路可能尚未打通，需一并排查**。

### v1.0.5 — 跳过「读凭据」，直接走配网

**真机日志（v1.0.4）证明通信链路已完全正确**：

| 校验项 | 结果 |
|---|---|
| CRC8（全部 24 帧） | ✅ 全部通过 |
| Sequence 分片级自增 | ✅ 发送 0..13 / 接收 0..8 |
| MORE 位（末片=0，其余=1） | ✅ 正确 |
| 密钥协商 | ✅ **成功**（12 片公钥 → 9 片响应，AES 密钥解出） |
| 加密请求 0x0D | ✅ 发出 2 片 / 16 字节密文（完整 AES 块） |

**唯一问题**：设备对 `0x0D`（查询设备信息）**完全不作响应** → 10 秒超时。

根因：**固件未实现 `0x0D` 的扩展响应分支**（也不返回 TLV `0x0A`/`0x0B`）。
而 `0x0A`（WiFi 配网）是设备原生支持的，一定会回复 `0x8A`。

**v1.0.5 的改动 —— 不再让"读凭据"阻塞流程：**

| 改动 | 说明 |
|---|---|
| 查询超时从 10s 缩短到 **3s** | 已知必然超时，不为它让用户白等 |
| 超时不再当错误处理 | 新增专用错误码 `STATUS_QUERY_INFO_UNSUPPORTED`，识别后**直接继续配网** |
| 凭据来源改为"优先设备、回退预置" | 固件升级后自动使用设备值，无需改代码 |
| 明文降级路径同步修正 | 原先降级后仍会去查询设备信息（同样超时），现改为直接配网 |

流程变为：
```
连接 → 密钥协商 →（查询设备信息，最多等 3s）
                     ├─ 设备回了 → 用设备凭据
                     └─ 没回     → 用预置凭据（apikey 内置 + deviceId 由 MAC 推导）
                  → 下发 WiFi（0x0A）→ 等 0x8A → 绑定完成
```

### v1.0.4 — 修正 BLE 通信时序

解压联盛德官方 Android Demo 源码逐行比对后，发现 **v1.0.3 对 Sequence 的"修复"方向是错的**，
并同时暴露出另外 3 个真实缺陷。v1.0.4 全部修正：

| # | 缺陷 | 官方 SDK 的做法 | v1.0.3 的错误做法 |
|---|---|---|---|
| 1 | **Sequence 语义** | **每个分片** seq +1（`mSendSequence.getAndIncrement()`） | 整条消息共用一个 seq |
| 2 | **分片发送节奏** | 阻塞等 `onCharacteristicWrite` 回调（超时 1s）才发下一片 | 写完延时 30ms 盲发下一片 → BLE 栈队列溢出丢包 |
| 3 | **无参数请求** | TLV 为空时**不生成帧**，需放零长占位 TLV | 查询设备信息**一帧都没发出去** |
| 4 | **连接优先级** | 连接后 `requestConnectionPriority(HIGH)` | 未设置 |

### v1.0.2 — 修复 Room 数据库不可用

**症状**（用户诊断页报告）：
```
本地数据库: ❌ 不可用
RuntimeException: Cannot find implementation for com.turing.thumbcard.data.db.AppDatabase.
AppDatabase_Impl does not exist
```

**根因**：`app/build.gradle` 只声明了 `room-runtime` / `room-ktx`，
**缺少注解处理器（KSP）**。Room 靠注解处理器在编译期生成 `AppDatabase_Impl`，
没有它就无法工作。

**修复**：
- `build.gradle`（根）加入 KSP 插件 `com.google.devtools.ksp:1.9.22-1.0.17`
- `app/build.gradle` 加入 `ksp 'androidx.room:room-compiler:2.6.1'`
- compileSdk / targetSdk 提升到 **35**

**验证**：已确认 APK 的 `classes10.dex` 中包含 `AppDatabase_Impl`、
`WordCardDao_Impl`、`BoundDeviceDao_Impl` 三个类。

### v1.0.1 — 修复华为鸿蒙 / 卓易通启动闪退


**根因**：原版在 `Application.onCreate()` 调用 `EncryptedSharedPreferences`。
在 Android 兼容容器（卓易通）中 Keystore 可能不完整，导致启动即崩。

**修复**（三层加固）：
1. 凭据存储三级降级：加密 → 明文 → 内存，任一级失败自动降级
2. 数据库容错：Room 失败返回 `null`，App 以「无本地缓存」模式继续
3. 全局崩溃兜底：崩溃落盘 + 下次启动弹窗提示

**新增**：诊断页（首页底部版本号可点）、离线演示模式。

> 💡 实测你这台 HUAWEI SCA-AL00（HarmonyOS 6 / Android 16 API 36）
> **Keystore 完全可用**，加密存储正常工作 —— 容器限制主要体现在别处。
