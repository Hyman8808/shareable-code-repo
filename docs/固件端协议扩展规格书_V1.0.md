# W800 蓝牙配网协议扩展规格书

**用于 AI 拍学机 / 拇指相机单词卡学习机项目**

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 编制日期 | 2026-10-16 |
| 适用芯片 | WinnerMicro W800 |
| 基线协议 | 《WM_W800_BleWiFi 蓝牙配网协议 V1.0》 |
| 改动范围 | 仅新增 TLV 字段与 1 条自定义命令，**不修改任何既有命令行为** |
| 对端 | Android / iOS / OpenHarmony App |

---

## 1. 背景与目标

### 1.1 现状

AI 拍学机设备通过 W800 模组的 BLE 通道完成 WiFi 配网，配网完成后设备接入 `nglearn.turingapi.com`，通过 WebSocket 上报拍照识别请求。云端会将每次识别结果留痕，App 可通过 REST 接口按 `deviceId` 拉取记录，在本地渲染为单词卡片。

### 1.2 问题

App 需要知道当前配网设备的 **apikey** 与 **deviceId** 才能拉取该设备的记录。但在基线协议中：

- apikey 已由产线烧录进设备，但**协议没有任何通道把它上报给 App**
- `0x0D 查询设备信息` 的响应 PAYLOAD 仅包含 WiFi 配置类字段（SSID / 密码 / BSSID），无法承载凭据

因此 App 无法获知 apikey 与 deviceId，绑定流程无法闭环。

### 1.3 目标

在**不破坏既有协议兼容性**的前提下，扩展「查询设备信息」响应的 TLV 字段，使 App 在配网过程中即可读取设备的 apikey 与 deviceId，完成绑定。

### 1.4 设计约束

| 约束 | 说明 |
|---|---|
| 向后兼容 | 既有命令的帧结构、TLV 类型、错误码**一律不变**，新字段为可选追加 |
| 改动最小 | 固件仅需在 `0x0D` 命令处理函数中追加 TLV 字段 |
| 出厂烧录 | apikey / deviceId 由产线写入 Flash，运行期只读 |
| 不引入新密钥 | 复用既有 RSA 协商得到的 AES-128 会话密钥加密传输 |

## 2. 协议变更总览

### 2.1 变更清单

| 编号 | 变更类型 | 命令码 | 内容 | 必要性 |
|---|---|---|---|---|
| C-1 | 新增 TLV（上行响应） | `0x8D` | `0x0A` = APIKEY | **必须** |
| C-2 | 新增 TLV（上行响应） | `0x8D` | `0x0B` = DEVICEID | **必须** |
| C-3 | 新增 TLV（上行响应） | `0x8D` | `0x0C` = ORG_ID（组织标识，可选） | 建议 |
| C-4 | 新增 TLV（上行响应） | `0x8D` | `0x0D` = DEVICE_TYPE（设备型号，可选） | 建议 |
| C-5 | 新增 TLV（上行响应） | `0x8D` | `0x0E` = FIRMWARE_VER（固件版本，可选） | 建议 |
| C-6 | 新增命令 | `0x11` | 下发 apikey/deviceId 校验回执（可选） | 可选 |

> **重要说明**：C-1 ~ C-5 全部挂在**已存在的 `0x8D` 响应**上，不新增命令码。App 侧解析逻辑只需在既有 TLV 解析循环后追加字段判断，**无需改动帧层实现**。
>
> C-6 为可选能力，用于 App 侧向设备回写「绑定已完成」，使设备可以点亮绑定指示灯或播放提示音。若本期不做设备端视觉反馈，可暂不实现。

### 2.2 为什么不新增独立命令

理论上可以新增一条 `0x11 GET_CREDENTIAL` 命令专门读取凭据。但：

- 新增命令需要协议版本号升位、双方同步升级，兼容成本高
- `0x0D 查询设备信息` 的语义本就包含「获取设备标识信息」，扩展 TLV 是语义最自然的做法
- 配网流程中 App 本来就会调用一次 `0x0D`，复用可减少一次交互往返

**结论：采用 TLV 扩展方案。**

## 3. 帧格式（不变，供实现参考）

### 3.1 通用帧结构

```
+--------+----------+--------+------+---------------+------+
|  Cmd   | Sequence |  Flag  |  NO  |    PAYLOAD    | CRC  |
+--------+----------+--------+------+---------------+------+
| 1 byte |  1 byte  | 1 byte |1 byte|    N bytes    |1 byte|
```

| 字段 | 说明 |
|---|---|
| Cmd | 操作码。App → 设备为原码，设备 → App 为 `原码 + 0x80` |
| Sequence | 序列号，从 0 开始，每帧 +1；重传时 +1 而 NO 不变 |
| Flag | Bit7=是否加密；Bit6=是否要求 Ack；Bit5=是否还有后续分片 |
| NO | 分片序号，从 0 开始；应用层重传时不变 |
| PAYLOAD | TLV 封装的消息内容 |
| CRC | `CRC8(Cmd + Sequence + Flag + NO + PAYLOAD)`，查表法（见附录 A） |

### 3.2 Flag 位定义

| Bit | 含义 | 取值 |
|---|---|---|
| [7] | 帧是否加密 | 1=加密，0=未加密。**仅 PAYLOAD 域加密** |
| [6] | 是否要求对方回复 Ack | 1=要求，0=不要求 |
| [5] | 是否还有后续分片 | 1=有后续，0=最后一帧 |
| [4:0] | 保留 | 置 0 |

### 3.3 TLV 编码

```
+--------+----------+------------------+
|  Type  |  Length  |      Value       |
+--------+----------+------------------+
| 1 byte |  1 byte  | Length 个字节     |
```

- `Type`：1 字节类型标识
- `Length`：1 字节，Value 的**实际字节数**（不含 Type 与 Length 自身）
- `Value`：原始字节。字符串类型按 **UTF-8 无终止符** 编码

### 3.4 分片规则

- PAYLOAD 组装完成后（如需加密则先加密），按 **14 字节** 切片（`PACKETMAXLENGTH800 = 14`）
- 每片作为一个独立帧发送，`NO` 依次递增
- 非末帧 `Flag[5] = 1`，末帧 `Flag[5] = 0`
- 加密时所有分片 `Flag[7] = 1`

> **注意**：14 字节是 W800 平台的 MTU 约束值，来自官方 Android SDK 的 `MessageEncode.serialize800()`。实现时必须严格保持，不得按 BLE 默认 MTU 调整。

## 4. 新增 TLV 定义（核心变更）

### 4.1 变更点：`0x0D` 查询设备信息 → `0x8D` 响应

**App 发送（不变）**

```
Cmd    = 0x0D
Flag   = 0x00
NO     = 0x00
PAYLOAD = 空
CRC    = CRC8(0x0D, Seq, 0x00, 0x00)
```

**设备响应（扩展后）**

```
Cmd    = 0x8D
PAYLOAD = [既有 WiFi 配置 TLV] + [新增设备凭据 TLV]
```

### 4.2 新增 TLV 字段表

| Type | 名称 | 长度 | 编码 | 说明 | 必要性 |
|---|---|---|---|---|---|
| `0x0A` | APIKEY | 32 | ASCII | 平台 Accesskey，32 位小写十六进制字符串 | **必须** |
| `0x0B` | DEVICEID | ≤18 | ASCII | 设备唯一标识，字母/数字组成，与云端 `deviceId` 一致 | **必须** |
| `0x0C` | ORG_ID | 2 | 小端 uint16 | BLE 广播包中的组织 ID（联盛德为 `0x070C`） | 建议 |
| `0x0D` | DEVICE_TYPE | 1 | uint8 | 设备型号编码，供 App 区分产品形态 | 建议 |
| `0x0E` | FIRMWARE_VER | 1 | uint8 | 固件版本，高 4 位主版本 + 低 4 位次版本（如 `0x12` = V1.2） | 建议 |

### 4.3 字段填充规范

#### 4.3.1 APIKEY（`0x0A`）

- **来源**：产线烧录区，建议独立 Flash 分区（如 `credential` 分区），避免与固件同区导致 OTA 覆盖
- **格式**：固定 32 字节，ASCII 小写十六进制，**无 `0x00` 终止符**
- **示例值**：`<DEVICE_API_KEY>`
- **读取失败处理**：若 Flash 校验失败，**不返回该 TLV**（而非返回空值），App 侧据此判定「设备未烧录凭据」

```
Type   = 0x0A
Length = 0x20  (32)
Value  = "<DEVICE_API_KEY>" 的 ASCII 字节
```

#### 4.3.2 DEVICEID（`0x0B`）

- **来源**：产线烧录区，与本设备上报云端的 `deviceId` **必须完全一致**
- **格式**：变长 ASCII，最长 18 字节，**无 `0x00` 终止符**
- **示例值**：`c8586a630100`（12 字节）
- ⚠️ **一致性红线**：该字段若与设备实际上报云端的 `deviceId` 不一致，App 将拉到空记录列表（云端接口对不存在的 deviceId 返回 200 + 空列表，不会报错），**故障排查极其困难**。产线需保证两者同源。

```
Type   = 0x0B
Length = 0x0C  (12)
Value  = "c8586a630100" 的 ASCII 字节
```

#### 4.3.3 ORG_ID（`0x0C`，建议）

- **来源**：固件编译期常量或烧录区
- **格式**：2 字节小端序
- **说明**：供 App 在扫描阶段过滤本厂设备。若产线已能通过广播包识别，此字段可省略

```
Type   = 0x0C
Length = 0x02
Value  = 0x0C 0x07   (小端表示 0x070C)
```

#### 4.3.4 DEVICE_TYPE（`0x0D`，建议）

- **格式**：1 字节无符号整数
- **建议编码**：`0x01` = 拇指相机，`0x02` = 后续机型…（由产品定义）

#### 4.3.5 FIRMWARE_VER（`0x0E`，建议）

- **格式**：1 字节，高 4 位主版本、低 4 位次版本
- **示例**：`0x12` 表示 V1.2

### 4.4 TLV 组装顺序（推荐）

```
[0x01 AP_SSID]          (既有，若有)
[0x02 AP_PASSWORD]      (既有，若有)
[0x03 AP_BSSID]         (既有，若有)
[0x0A APIKEY]           (新增)
[0x0B DEVICEID]         (新增)
[0x0C ORG_ID]           (新增)
[0x0D DEVICE_TYPE]      (新增)
[0x0E FIRMWARE_VER]     (新增)
```

> 顺序不影响解析正确性（TLV 按 Type 索引），但固定顺序便于抓包比对与测试。

### 4.5 加密方式

**沿用既有机制，不引入新算法：**

- 若 RSA 密钥协商已完成（App 已拿到 AES-128 会话密钥），则 `0x8D` 响应 `Flag[7] = 1`，PAYLOAD 整体用 **AES-128/ECB/PKCS7** 加密后再分片
- 若未协商密钥，则以明文传输

> ⚠️ **实现注意**：官方 Android SDK 使用的是 **ECB 模式**（`AESUtils` 中 `Cipher.getInstance("AES/ECB/PKCS7Padding")`），而基线协议文档第 2 节描述为 **CBC 模式**。**两者矛盾，以官方代码 ECB 为准。** 本扩展沿用 ECB，以保持与 Android / iOS / 小程序三端既有实现一致。
>
> 建议：本期不做加密模式变更。若后续要升级到 CBC/GCM，需三端同步，属于独立议题。

## 5. 可选命令 C-6：绑定结果回执

### 5.1 用途

App 在完成「拉取记录 + 建立本地绑定关系」后，向设备回写一条确认，使设备可以：

- 点亮绑定成功指示灯 / 熄灭配网指示灯
- 播放「绑定完成」语音提示
- 在本地标记已绑定状态，避免重复配网

**本期若无需设备端反馈，可跳过此命令，不影响绑定流程闭环。**

### 5.2 命令定义

**App → 设备：`0x11` BIND_RESULT**

```
Cmd     = 0x11
Flag    = 0x80 (加密) 或 0x00 (明文)
NO      = 0x00
PAYLOAD = TLV: 0x0F = BIND_STATUS
CRC     = CRC8(...)
```

| Type | 名称 | 长度 | 取值 |
|---|---|---|---|
| `0x0F` | BIND_STATUS | 1 | `0x00` = 绑定成功；`0x01` = 绑定失败；`0x02` = 用户取消 |

**设备 → App：`0x91` 响应**

```
Cmd     = 0x91
PAYLOAD = TLV
```

| Type | 名称 | 长度 | 取值 |
|---|---|---|---|
| `0x81` | Error_ID | 1 | `0x00` 成功；`0x01` 参数错误 |

### 5.3 设备端行为建议

| BIND_STATUS | 建议行为 |
|---|---|
| `0x00` 绑定成功 | 绿灯常亮 3 秒，播放「绑定成功」；关闭 BLE 广播 |
| `0x01` 绑定失败 | 红灯闪烁 3 次；保持 BLE 广播可重试 |
| `0x02` 用户取消 | 无动作；保持 BLE 广播 |

## 6. 错误码

沿用基线协议错误码，**不新增**：

| 错误码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 参数错误 |
| 2 | 密码错误 |
| 3 | 获取 IP 地址失败 |
| 4 | 扫描失败 |
| 5 | 秘钥交换失败 |
| 6 | 发送数据失败 |

**新增建议（可选）**：若产线未烧录凭据，建议 `0x8D` 响应中**不返回** `0x0A` / `0x0B` 字段，由 App 判定「设备无凭据」，**不引入新错误码**，避免破坏既有错误码表。

## 7. 完整报文示例

以下示例基于真实测试设备，`deviceId = c8586a630100`，`apikey = <DEVICE_API_KEY>`。

### 7.1 步骤 1：App 请求查询设备信息

```
发送帧（6 字节）:
0D 00 00 00 CRC

Cmd    = 0x0D
Seq    = 0x00
Flag   = 0x00
NO     = 0x00
PAYLOAD= (空)
CRC    = CRC8([0x0D,0x00,0x00,0x00], 4, 0)
```

### 7.2 步骤 2：设备明文响应（未加密场景）

假设仅返回新增字段（实际会与 WiFi 配置 TLV 一起返回）：

**TLV 拼装前（明文）**

```
Type  Len  Value
0A    20   32 63 61 64 37 34 32 65 30 31 30 37 34 32 31 34 61 66
           34 32 64 38 62 37 62 31 32 62 38 35 31 39
           ("<DEVICE_API_KEY>")
0B    0C   63 38 35 38 36 61 36 33 65 32 30 65
           ("c8586a630100")
0C    02   0C 07
0D    01   01
0E    01   12
```

**明文 PAYLOAD 总长** = (2+32) + (2+12) + (2+2) + (2+1) + (2+1) = 58 字节

**分片（每片 14 字节）** → 5 片

| NO | Flag | 长度 | 说明 |
|---|---|---|---|
| 0 | `0x20` | 14 | 有后续（Bit5=1） |
| 1 | `0x20` | 14 | 有后续 |
| 2 | `0x20` | 14 | 有后续 |
| 3 | `0x20` | 14 | 有后续 |
| 4 | `0x00` | 2 | 末帧（Bit5=0） |

**第 0 帧完整字节**

```
8D 00 20 00 0A 20 32 63 61 64 37 34 32 65 30 31 30 37 CRC

Cmd    = 0x8D
Seq    = 0x00
Flag   = 0x20  (最后一帧标记为"有后续")
NO     = 0x00
PAYLOAD= 0A 20 32 63 61 64 37 34 32 65 30 31 30 37  (14 字节)
CRC    = CRC8(前 18 字节, 18, 0)
```

### 7.3 步骤 3：设备加密响应（推荐场景）

若已完成密钥协商：

```
Flag[7] = 1，PAYLOAD 先经 AES-128/ECB/PKCS7 加密
58 字节明文 → PKCS7 填充至 64 字节 → ECB 加密 → 64 字节密文
→ 按 14 字节分片 → 5 片（前 4 片 14 字节，末片 8 字节）
每片 Flag = 0x80 | 0x20(有后续) 或 0x80(末片)
```

> App 侧解密后得到明文 TLV 流，再按 Type 逐字段解析。

### 7.4 边界情况：设备未烧录凭据

**设备响应中不含 `0x0A` / `0x0B` 字段**，App 应提示：

>「设备未写入凭据，请检查产线烧录或联系售后」

**不得**返回空字符串或全 `0x00`，否则 App 会误判为有效凭据并发起无效请求。

## 8. 固件改动点（给固件工程师）

### 8.1 改动位置

| 模块 | 函数/位置 | 改动内容 |
|---|---|---|
| BLE 命令处理 | `0x0D 查询设备信息` 的响应组装处 | 在既有 TLV 之后追加 `0x0A` ~ `0x0E` 字段 |
| 凭据读取 | 新增 `credential_read()` | 从 Flash 烧录区读取 apikey / deviceId，含 CRC 校验 |
| 烧录工具 | 产线烧录脚本 | 增加 credential 分区写入 |

### 8.2 伪代码

```c
/* 在 0x0D 命令的响应组装流程中插入 */

static int handle_query_device_info(uint8_t *out_buf, int *out_len)
{
    int pos = 0;

    /* ===== 既有逻辑：写入 WiFi 配置 TLV（保持不变） ===== */
    pos += tlv_write_string(out_buf + pos, 0x01, cfg.ssid);
    pos += tlv_write_string(out_buf + pos, 0x02, cfg.password);
    pos += tlv_write_bytes (out_buf + pos, 0x03, cfg.bssid, 6);

    /* ===== 新增：写入设备凭据 TLV ===== */
    char apikey[33]   = {0};
    char device_id[19] = {0};

    if (credential_read(apikey, device_id) == 0) {
        /* 读取成功才写入，失败则整体省略这两个字段 */
        pos += tlv_write_string(out_buf + pos, 0x0A, apikey);
        pos += tlv_write_string(out_buf + pos, 0x0B, device_id);
    }

    /* ===== 新增：可选字段 ===== */
    uint8_t org_le[2] = { (uint8_t)(ORG_ID & 0xFF),
                          (uint8_t)((ORG_ID >> 8) & 0xFF) };
    pos += tlv_write_bytes (out_buf + pos, 0x0C, org_le, 2);
    pos += tlv_write_byte  (out_buf + pos, 0x0D, DEVICE_TYPE);
    pos += tlv_write_byte  (out_buf + pos, 0x0E, FIRMWARE_VER);

    *out_len = pos;
    return 0;
}

/* TLV 辅助函数 */
static int tlv_write_string(uint8_t *buf, uint8_t type, const char *str)
{
    uint8_t len = (uint8_t)strlen(str);
    buf[0] = type;
    buf[1] = len;
    memcpy(buf + 2, str, len);
    return 2 + len;   /* 注意：不含 0x00 终止符 */
}

static int tlv_write_bytes(uint8_t *buf, uint8_t type,
                           const uint8_t *val, uint8_t len)
{
    buf[0] = type;
    buf[1] = len;
    memcpy(buf + 2, val, len);
    return 2 + len;
}

static int tlv_write_byte(uint8_t *buf, uint8_t type, uint8_t val)
{
    buf[0] = type;
    buf[1] = 1;
    buf[2] = val;
    return 3;
}
```

### 8.3 凭据读取与校验

```c
#define CRED_MAGIC   0x43454431u   /* "CED1" */
#define CRED_OFFSET  0x001F0000u   /* 示例偏移，以实际分区表为准 */

typedef struct {
    uint32_t magic;
    char     apikey[32];
    char     device_id[18];
    uint8_t  reserved[2];
    uint32_t crc32;               /* 覆盖 magic + apikey + device_id */
} credential_t;

static int credential_read(char *apikey_out, char *device_id_out)
{
    credential_t cred;

    if (flash_read(CRED_OFFSET, &cred, sizeof(cred)) != 0) {
        return -1;
    }
    if (cred.magic != CRED_MAGIC) {
        return -1;                       /* 未烧录 */
    }
    if (crc32_calc(&cred, sizeof(cred) - 4) != cred.crc32) {
        return -1;                       /* 校验失败 */
    }

    memcpy(apikey_out,   cred.apikey,   32);   apikey_out[32]  = '\0';
    memcpy(device_id_out, cred.device_id, 18); device_id_out[18] = '\0';

    /* 校验 deviceId 合法性：字母/数字，长度 1~18 */
    size_t n = strlen(device_id_out);
    if (n == 0 || n > 18) {
        return -1;
    }
    for (size_t i = 0; i < n; i++) {
        char c = device_id_out[i];
        if (!((c >= '0' && c <= '9') ||
              (c >= 'a' && c <= 'z') ||
              (c >= 'A' && c <= 'Z'))) {
            return -1;
        }
    }
    return 0;
}
```

### 8.4 内存与分片注意

- 明文 PAYLOAD 约 58 字节，加 WiFi 配置 TLV 后可能超过 100 字节
- 加密后需 PKCS7 填充，长度向上取整到 16 的倍数
- 分片缓冲建议 **≥256 字节**，避免 `turing` 等长 SSID 场景溢出
- **必须复用既有分片函数**，`PACKETMAXLENGTH800 = 14` 不可改

## 9. 兼容性说明

### 9.1 对既有 App 的影响

| 场景 | 行为 |
|---|---|
| 旧版 App + 新固件 | 旧 App 遍历 TLV 时遇到未知 Type 会**跳过**（按 Length 前进），无影响 |
| 新版 App + 旧固件 | 新 App 找不到 `0x0A`/`0x0B` 字段，提示「设备未烧录凭据」并引导升级固件 |
| 新版 App + 新固件 | 正常读取凭据，绑定闭环 |

> **前提**：App 侧 TLV 解析必须是「按 Length 跳过未知类型」的健壮实现，而非「遇到未知类型就报错」。官方 Demo 已是健壮实现（`decode()` 循环中按 `length` 前进），无需改动。

### 9.2 协议版本号

建议将广播包 `Version` 字段由 `0x10` 升至 `0x11`，供 App 识别固件是否支持凭据上报。若不便变更，App 侧可直接以「是否解析到 `0x0A` 字段」作为能力探测。

## 附录 C：与 Android SDK 的对应关系

固件实现完成后，Android 侧只需在现有 `MessageEncode.decode()` 解析结果中读取新 Type 即可，**无需修改帧层、加密层、分片层**：

```java
// 现有代码已能解析全部 TLV，直接读取新字段
byte[] apikeyBytes  = mObjects.get(0x0A);
byte[] deviceIdBytes = mObjects.get(0x0B);

String apikey   = apikeyBytes   != null ? new String(apikeyBytes,   "UTF-8") : null;
String deviceId = deviceIdBytes != null ? new String(deviceIdBytes, "UTF-8") : null;

if (apikey == null || deviceId == null) {
    // 设备未烧录凭据
}
```
