# 拇指相机样机联调清单（App v2.11.1）

> 适用：拿到首批样机、要验证「BLE 配网 → 绑定 → 拉卡」整条链路。
> 判据全部写明「看到什么算通过」，不依赖研发口头确认。
> 抓不到 logcat 的机器（该 ROM 常见）全部靠 App 内置日志面板，见 §5。

---

## 1 装包

| 项 | 值 |
|---|---|
| 主线包 | `release/单词卡相机_v2.11.1_debug.apk`（10,271,313 B，vc 46） |
| AI 包 | `release/单词卡相机AI_v2.11.1_debug.apk`（10,271,370 B，vc 46） |
| 最低系统 | Android 6.0（API 23） |

```bash
adb install -r 单词卡相机_v2.11.1_debug.apk
# 若中文路径报错，先复制成英文名再装
cp 单词卡相机_v2.11.1_debug.apk /tmp/tc.apk && adb install -r /tmp/tc.apk
```

**权限必须全给**：Android 12+ 是「附近的设备」一组（BLUETOOTH_SCAN / CONNECT），
Android 11 及以下是「位置信息」——少给一个，扫描直接返回空列表，且**不报错**。

## 2 现场五步验收

| 步 | 动作 | 通过判据 | 不通过看 |
|---|---|---|---|
| ① | 相机开机，靠近手机 | 「添加设备」页 15s 内出现设备，名字形如 `AIPicCamera3F2A` 或旧名 `WM-xxxx` | §3.1 |
| ② | 点设备 → 进 WiFi 页 | 日志出现「设备已连接」→「服务发现完成」→「密钥协商成功」 | §3.2 |
| ③ | 等列表 | 2~4s 内出现热点列表，按信号从强到弱，加密的带锁图标 | §3.3 |
| ④ | 点 2.4G 热点 → 输密码 → 连接 | 日志「配网成功 IP=…」，随后「建立绑定关系」 | §3.4 |
| ⑤ | 回首页 | 出现该设备，能拉到记录（首次为空是正常的，先拍一张） | §3.5 |

> ③ 若 6s 还没列表，页面会自己亮出「手动输入 WiFi」按钮 —— 这是给未升级固件的兜底，
> 出现它不等于 App 坏了，但**说明固件没实现 V1.2 列表能力**，记下来（§4 第 1 项）。

## 3 失败判别与处置

### 3.1 扫不到设备

| 现象 | 原因 | 处置 |
|---|---|---|
| 完全没有任何设备 | 权限没给全 | 设置 → 应用 → 权限，把「附近的设备/位置信息」全开；Android 12+ 还需打开**系统定位开关** |
| 只有别的设备，没有相机 | 广播里既无 `ORG-ID=0x070C`，名字也不以 `AIPicCamera` 开头 | 用 nRF Connect 看广播原始字节，把 `0xFF` 段和 `0x09` 段截图给固件（§4 第 2 项） |
| 有名字但点进去连不上 | 广播 MAC 与可连接 MAC 不同（末位差 1） | 属 BLE 常态，App 已用连接地址；仍失败则是设备已被别的手机占着连接，先断开那台 |

### 3.2 连上了但协商不过

日志会走到「切换明文模式，重新连接设备」—— **这是设计好的降级，不是 bug**。
W800 若对 RSA 公钥请求回的内容不合规范，App 会自动改走明文完成配网（内网环境可接受）。

若明文也失败（日志出现「配网失败」且错误码不是 0）：

| 错误码 | 含义 | 处置 |
|---|---|---|
| 2 | 找不到该 SSID | SSID 拼错，或设备扫不到 5G（只支持 2.4G） |
| 3 | 密码错误 | 重输；注意大小写与中文全角 |
| 4 | 连接超时 | 路由器开了 MAC 白名单 / 该 AP 是 5G |
| 8 | 设备扫描中 | 等 3s 再点刷新（App 已节流） |
| 9 | 没有可用 AP | 设备周围确实扫不到 2.4G，换位置 |

### 3.3 列表一直不来

按 6s 后是否出现「手动输入 WiFi」分两种：

- **出现了** → 固件是 V1.0 基线，不认 `0x0E` 扫描指令。点手动输入完成配网，同时记录 §4 第 1 项，等固件升级后再验列表。
- **没出现且一直转圈** → App 侧扫描回调没回来，把 App 日志面板整段复制出来（右上角「复制日志」）。

### 3.4 配网成功但绑定失败

| 现象 | 原因 |
|---|---|
| 日志「设备上报 MAC」与预期不符 | 广播 MAC 末位 +1 属正常，App 已用 `0x8A` 里的 MAC 校正 deviceId |
| 绑定后首页仍为空 | 云端按 deviceId 过滤，用错 deviceId 就永远空 —— 去「我的 → 诊断」看当前 deviceId 是否等于 `0x8A` 上报值 |

### 3.5 拉不到卡

先手动拍一张，再回首页下拉刷新。仍为空则查 `apikey`：
预置 apikey 是整批公用的测试值，若样机是**另一批烧录**，apikey 会不同 →
日志里「apikey = 2cad****8519（预置测试值）」这一行就是判据。

## 4 必须现场确认的五个固件事实

这五项决定后续 3 周能不能排开，请逐项记录「是/否 + 证据」：

| # | 事实 | 怎么查 | 影响 | 实测（2026-10-26，用联调工具） |
|---|---|---|---|---|
| 1 | 是否实现 `0x88`/`0x89` 列表 TLV | 看 §2 第 ③ 步是否 4s 内出列表 | 否则只能用 §3.3 的兜底，列表式配网体验上不了 | ❌ **未实现**。`0x0E` 发出后只回一帧 `0E 0F 80 01 71 3B BD`，15s 内无任何列表帧 |
| 2 | 广播包 `0xFF` 段是否含 `0C 07`（ORG-ID 小端） | nRF Connect 看原始字节 | 决定 App 走主通道还是名字兜底 | ✅ **有**。App 按 ORG-ID `0x070C` 过滤到了设备（两台都在，广播名 `WM-63:82:23`，不是 `AIPicCamera` 前缀） |
| 3 | 广播 `Version` 字段是 `0x11` 还是 `0x12` | 同上，第 4 字节 | App 据此选列表解析格式 | ⚠️ **都不是，是 `0x10`**，而 `0x8D` 自报固件 `1.1 (0x11)`。两者不一致，**请固件升级时同步改广播 Version** |
| 4 | `0x8D` 是否回 5 个 TLV（`0x0A`~`0x0E`） | 日志「✓ 设备返回凭据」还是「设备未返回凭据」 | 否则 apikey/deviceId 只能靠预置+MACC 推导 | ✅ **5 个全回**：apikey `2cad74…8519`、deviceId `c8586a630000`、ORG-ID `0x070C`、型号 `1`、固件 `1.1` |
| 5 | 是否回 `0x10` Ack | 日志无「重发」字样 | 不回会让多分片响应变慢 | ⬜ 待看报文逐帧确认（联调工具「报文」页可自查） |

## 5 抓日志（无 logcat 时）

该 ROM 抓不到 `Log.d`，全部走 App 内置面板：

1. 配网页底部日志区，实时打印每一步（连接/协商/查询/扫描/下发/结果）
2. 该区域显示后，底部出现「复制日志」按钮 → 复制到剪贴板 → 发到工单
3. 日志含原始报文十六进制（`traffic` 段），固件同事可直接对照帧格式定位

需要系统级 logcat 时：

```bash
adb logcat -c && adb logcat | grep -iE "Ble|Wifi|ThumbCard"
```

⚠️ 屏幕会自动黑屏，先唤醒再截图：

```bash
adb shell input keyevent KEYCODE_WAKEUP
adb shell screencap -p /sdcard/s.png && adb pull /sdcard/s.png
```
