### 登录：小程序只做微信，不做支付宝（2026-10-28 定）

App 的 `LoginActivity` 是三渠道（微信 / 支付宝 / 手机号），三个都只弹「开发中」。小程序按现实重做：

| 方式 | 小程序 | 理由 |
|---|---|---|
| 微信一键登录 | ✅ 实现完成 | 小程序只能跑在微信里，`wx.login` 零输入零短信成本 |
| 支付宝登录 | ❌ 不做 | 那是**支付宝小程序**的 SDK，微信小程序里没有这个入口，也不需要 |
| 手机号验证码 | 降为可选绑定 | 只用于换手机找回，不作首登门槛（0.05 元/条） |

🔴 **接口现状**：`POST /v1/auth/wx` 目前不存在（#2835 账号域 16 接口里没有这一路）。
客户端**没有**做假登录态 —— 点了会明确显示「云端登录接口还没上线」，并附上原因。契约已写进
`docs/小程序微信登录_接口需求_2026-10-28.md`，王秀文实现后客户端零改动即可用。

🔴 **iOS 耦合**：iOS App 一旦接微信登录，按 App Store 4.8 必须同时补 Sign in with Apple。
本版 iOS 只走手机号 → 豁免。这个耦合关系别只在一端加。

## 四、🔴 词典接口：本次实测结论

| 项 | 结果 |
|---|---|
| 地址 | `wss://ws-api.turingapi.com/api/v2`（App 用 `ws://`，小程序只允许 wss，**wss 实测可用**） |
| 请求 | `{key, timestamp, data}`，`data` 为**明文字符串**（文档说的 AES 密文服务端返回 4008） |
| 帧序 | `210 参数初始化成功` → `220 参数上传完成` → `200 success` + `done:true` |
| 时延 | 握手 510ms / 全链路 **729ms** |
| 结构 | `en_word` 有音标+释义+例句+词形；`cn_word` 有拼音+汉语释义；`others` 只有机翻 |
| 鉴权 | key 用**当前设备的 apikey**（与记录接口同一个 key） |

## 六、已知差异（不是 bug）

| 差异 | 原因 |
|---|---|
| 繁体对「干 / 面 / 台」这类多形字不转换 | App 用 Android ICU 词典转换，小程序只有内置字表（≈230 对） |
| 选日语/阿语时中文栏仍显示简体 | 老栈 `lang` 参数未生效（方案 A 未上线）；详情页会明确标注「暂无该语言译名」 |
| 收藏页名称是收藏那一刻的 | 老栈没有按 id 批量取接口，收藏存的是行快照；点进详情拿最新 |
| 配网页阿语文案是英文 | 同第三节，待母语校对 |
| 没有 AI 美化 / 批量修复 | 密钥必须在服务端 |
| 没有「从相册找回」 | 小程序拿不到静默读相册权限，只能用户主动选图 |

顺带修掉一个真实隐患：`pages/diagnose._sys()` 里 `wx.getDeviceInfo()` 若存在但返回 `undefined`（部分基础库版本），
