## 1. 总则

### 1.1 域名

| 环境 | 地址 |
|---|---|
| prod | `https://thumbcamera-api.turingapi.com` |

### 1.2 三套凭证，不要混用

| 凭证 | 谁持有 | 能调什么 | 不能做什么 |
|---|---|---|---|
| `bootstrapToken`（`tcb_…`） | 配网工具 / 产线 | `POST /v1/devices` 建设备 | 不能读卡片 |
| `clientToken`（`tcc_…`） | App / 小程序 | `/client/v1/*` 全部 | 不能上传识别 |
| `Device-Key` | 烧在设备里 | `/v1/device/*`（含 `config`） | **不能改语言**（改语言是客户端的事，实测 401） |

三种都用 `Authorization: Bearer <token>`。

> ⚠️ 设备侧还要带 `Device-Id` 头。`Device-Key` 和 `Device-Id` 必须配对，错配返回 `40101`。

### 1.3 🔵 统一响应与 `code` 语义

**成功一律 `code: 0`。** 不是 HTTP 200、不是 `code:200`。HTTP 状态码另有含义（401 表示凭证问题）。

```json
{"code":0,"data":{...}}
```

```json
{"code":40101,"message":"unauthorized"}
```

> 🟡 提醒：老云端 `nglearn` 用的是 `{"code":200,...}`。两套千万别混判——客户端写 `if (code == 200)` 对接新云端会**全部当失败**。

### 1.4 错误码

| code | HTTP | 含义 | 设备/客户端动作 |
|---|---|---|---|
| `0` | 200 | 成功 | — |
| `40001` | 400 | 请求体不是合法 JSON / 必填缺失 | 修请求，不重试 |
| `40101` | 401 | 凭证无效或与 `Device-Id` 不匹配 | 不重试，走重新配网 |
| `40301` | 403 | 🔴 该设备不属于当前凭证 | 不重试，提示无权限 |
| `40401` | 404 | 设备 / 记录不存在 | 提示未注册 |
| `42901` | 429 | 触发限流 | 指数退避 |

## 2. 设备侧接口（5 个）

### 2.1 `POST /v1/devices` —— 建设备（配网时一次）

`Authorization: Bearer <bootstrapToken>`

```json
{"deviceId":"cam-001","deviceKey":"probe0123456789abcdef","lang":"zh"}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `deviceId` | string | 是 | 设备唯一标识。**必须用云端下发的 ID**，不要用 BLE 广播 MAC（末位 +1 会错） |
| `deviceKey` | string | 是 | 设备密钥，随机 ≥16 字符，烧进设备 |
| `lang` | string | 否 | 初始物品语言，默认 `zh` |

> ⚠️ 幂等：同 `deviceId` 重复建，以最后一次为准。

### 2.2 `POST /v1/device/uploads` —— 申请直传

`Authorization: Bearer <Device-Key>` + `Device-Id`

```json
{"contentType":"image/jpeg","ext":"jpg"}
```

响应：

```json
{"code":0,"data":{
  "key":"thumb-camera/20261025/19f33ba6-....jpg",
  "putUrl":"https://turing-file.oss-cn-beijing.aliyuncs.com/thumb-camera/..."
}}
```

拿到 `putUrl` 后**直接 PUT 二进制**到 OSS，不要带 Authorization。

### 2.3 `POST /v1/device/photos` —— 提交识别

```json
{"key":"thumb-camera/20261025/19f33ba6-....jpg","contentType":"image/jpeg"}
```

响应：`{"code":0,"data":{"photoId":"<uuid>"}}`

### 2.4 `GET /v1/device/photos/{photoId}` —— 轮询结果

**建议 2s 一次，最多 20 次（40s）。**

```json
{"code":0,"data":{
  "status":"ok",
  "en":"iced cola",
  "name_english":"iced cola",
  "name_localized":"아이스 콜라",
  "name_localized_lang":"ko",
  "localized_status":"ok",
  "description_localized":"...",
  "pinyin":"",
  "phonetic":"/aɪstˈkəʊlə/",
  "tts_url_english":[],
  "tts_url_localized":[],
  "expire_at":"2026-10-31T16:41:55Z"
}}
```

| `status` | 含义 | 设备动作 |
|---|---|---|
| `pending` | 识别中 | 继续轮询 |
| `ok` | 成功 | 显示 + 播报 |
| `failed` | 识别失败 | 显示"没认出来"，不要播报 |

> 🔴 **语言从哪来**：不是设备传的，是云端按 `deviceId` 查这台设备的设定语言后**服务端自己翻的**。
> 设备只要读 `name_localized` / `tts_url_localized` 即可，不需要传任何语言参数。

### 2.5 🔴 `POST /v1/device/config` —— 读取并纠正语言（v1 缺失）

#### 2.5.1 为什么需要

App 改语言只写云端，**云端不会推给设备**（没有 MQTT/WebSocket 通道）。这是**拉取模型**：设备不问，语言永远不变。

#### 2.5.2 请求

```json
POST /v1/device/config
Authorization: Bearer <Device-Key>
Device-Id: cam-001
Content-Type: application/json

{"item_lang":"zh","ui_lang":"zh"}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `item_lang` | string | 是 | 设备**当前**物品语言（识别结果翻译成什么语言） |
| `ui_lang` | string | 是 | 设备**当前**界面语言（屏显提示、按键菜单） |

> ⚠️ 必须用**下划线** `item_lang` / `ui_lang`。
> 传 `itemLang` / `uiLang` / `lang` **不报错，但被静默忽略**，云端视为"设备没上报"，`reported_*` 返回空串——排查时最容易被这个坑住。

#### 2.5.3 响应

```json
{"code":0,"data":{
  "deviceId":"cam-001",
  "item_lang":"ja",
  "ui_lang":"ja",
  "reported_item_lang":"zh",
  "reported_ui_lang":"zh",
  "corrected":"true"
}}
```

| 字段 | 说明 |
|---|---|
| `item_lang` / `ui_lang` | **云端权威值，设备要用这个** |
| `reported_item_lang` / `reported_ui_lang` | 回显设备刚上报的值（空串 = 没解析到） |
| `corrected` | `"true"` = 与云端不一致，需要切换；注意是**字符串**不是布尔 |

#### 2.5.4 设备端处理

```
收到响应
├─ corrected == "true"
│    ├─ 把本地 item_lang / ui_lang 改成响应里的值
│    ├─ 更新屏显/菜单语言（ui_lang）
│    ├─ 更新 TTS 播报语言（item_lang）
│    └─ 存 NVS/Flash，下次开机直接用
└─ corrected == "false"
     └─ 什么都不做
```

#### 2.5.5 调用时机

| 时机 | 必要性 | 理由 |
|---|---|---|
| 开机联网成功后 | **必须** | 覆盖"关机期间 App 改了语言" |
| WiFi 重连成功后 | 必须 | 同上 |
| 每次拍照识别前 | 建议 | 让"刚改的语言"对下一张立刻生效 |
| 空闲每 5~10 分钟 | 可选 | 缩短时延；功耗考虑，建议只在充电时做 |

> 产品口径：**"App 改语言后，设备下一次开机或下一次拍照时生效"**。
> 要"按下立刻变"只有两条路：① 设备保长连接（W800 功耗不允许）；② App 走 BLE 直连下发（当前对方 App 无蓝牙权限）。

#### 2.5.6 语言枚举（固件只认这 9 个）

| 值 | 语言 | 值 | 语言 | 值 | 语言 |
|---|---|---|---|---|---|
| `zh` | 简体中文 | `ko` | 韩语 | `de` | 德语 |
| `zh-Hant` | **繁体中文** | `es` | 西班牙语 | `ru` | 俄语 |
| `en` | 英语 | `fr` | 法语 | `ja` | 日语 |

> 🔴 **繁体是独立语言**，不是简体的字体变体。字形、用词、读音都不同（「软体」vs「軟體」）。
> 服务端必须独立翻译，**禁止用简体文本走字符映射糊假繁体**。
> 语言码统一 `zh-Hant`，不用 `zh-TW` / `zh-HK`（兼容期服务端可接受后两者并归一）。
>
> 🔴 云端目前**不做白名单校验**（传 `xx`、`EN`、`中文` 都照存）。固件收到不认识的值**按 `en` 兜底**，把原值原样回报，不要崩。

## 3. 客户端接口（6 个）

### 3.1 `GET /client/v1/devices/{deviceId}` —— 读设备配置

```json
{"code":0,"data":{
  "deviceId":"cam-001","lang":"ja","uiLang":"ja","cloudDays":7,
  "createdAt":"...","updatedAt":"..."
}}
```

### 3.2 🟡 `PATCH /client/v1/devices/{deviceId}` —— 改设备配置

```json
{"lang":"ko","uiLang":"ko"}
```

| 字段 | 客户端可写 | 说明 |
|---|---|---|
| `lang` | ✅ | 物品语言（识别结果翻译目标） |
| `uiLang` | ✅ | 设备界面语言 |
| `cloudDays` | 🔴 **改为不可写** | 见 §4.2 |

响应返回**完整三元组**，客户端以此为准刷新界面。

### 3.3 `GET /client/v1/cards` —— 记录列表

```
GET /client/v1/cards?deviceId=cam-001&limit=20&cursor=<nextCursor>
Authorization: Bearer <clientToken>
```

| 参数 | 说明 |
|---|---|
| `limit` | 1~100，默认 20 |
| `cursor` | 上页返回的 `nextCursor`，首页不传 |

响应：

```json
{"code":0,"data":{
  "items":[{...}],
  "nextCursor":"c8d74ec4-90cc-4dc5-ad4d-94213e51451e"
}}
```

> 🟡 **修正 off-by-one**：当前 `limit=1` 实测返回 **2 条**。实现里应严格 `items.size <= limit`，超出部分由 `nextCursor` 交给下一页。

**记录字段（`items[]`）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | **string(uuid)** | 🔴 不是数字。客户端数据层主键必须是字符串 |
| `deviceId` | string | 所属设备 |
| `seq` | int | 设备内序号 |
| `en` | string | 英文名（词头） |
| `name_english` | string | 英文名（同 `en`，保留兼容） |
| `word` | string | 当前语言下的显示名 = `name_localized` 兜底 `name_english` |
| `name_localized` | string | 设定语言的名称 |
| `name_localized_lang` | string | 上面那个名称的语言码 |
| `localized_status` | string | `ok` / `pending` / `failed` |
| `description_localized` | string | 设定语言的释义 |
| `pinyin` | string | 拼音（中文时） |
| `phonetic` | string | 音标 |
| `tts_url_english` | string[] | 英文朗读音频 |
| `tts_url_localized` | string[] | 设定语言朗读音频 |
| `url` | string | 原图 |
| `hasImage` | bool | 图片是否还在（过期后 false） |
| `favorited` | bool | 收藏 |
| `status` | string | 识别状态 |
| `expire_at` | string(ISO8601) | 🔴 记录创建时**落库**的确定值 |
| `createdAt` / `recognizedAt` | string(ISO8601) | 时间 |

### 3.4 🔴 `GET /client/v1/cards/today` —— 今日卡（去重后）

```
GET /client/v1/cards/today?deviceId=cam-001
```

返回**最多 4 张**，按 `seq` 倒序。去重规则见 §4.3。

### 3.5 `GET /client/v1/cards/{id}` —— 单卡详情

`GET /client/v1/cards/178125a7-8979-4e17-87ae-1f41c7292716`

返回字段同 §3.3 的单条。**`{id}` 是 UUID 字符串。**

### 3.6 `PUT /client/v1/cards/{id}/favorite` —— 收藏

```
PUT /client/v1/cards/{id}/favorite?deviceId=cam-001
```

幂等：重复调用不报错。

## 4. 四个 P0 缺陷 —— 修复规格

> 这四个都是**服务端**问题，客户端的任何改动都绕不开。按优先级排序。

### 4.1 🔴 共享令牌可跨设备读全库

**现状（实测）**

`clientToken` 全局唯一、所有用户共享；`deviceId` 由客户端在 query 里自己传；服务端**不校验归属**。

```bash
# 用 A 设备的 token，读 B 设备的记录
curl "https://thumbcamera-api.turingapi.com/client/v1/cards?deviceId=eval-2729-probe-B&limit=5" \
  -H "Authorization: Bearer <clientToken>"
# → 200，返回 B 的全部记录
```

**影响**：任何人拿到一个 token，只要知道（或猜）别人的 deviceId，就能读全库照片和记录。上线即事故。

**修复规格（分两步）**

1. **过渡方案（账号体系上线前）** —— 一机一令牌
   - `clientToken` 改为**按设备签发**，签发时绑定 `deviceId`
   - `/client/v1/*` **移除 `deviceId` 入参**，服务端从令牌反查
   - 若请求仍带了 `deviceId` 且与令牌不符 → `40301`

2. **终态（有账号后）**
   - 令牌绑定 `userId`；`device.userId` 建立归属
   - 每次请求校验 `device.userId == token.userId`
   - 一个账号可绑多设备，但**只能读自己名下的**

> 验收用例：拿 A 的令牌请求 B 的 `deviceId`，必须 `40301`；不带 `deviceId` 时只返回 A 名下的卡。

### 4.2 🔴 `cloudDays` 客户端可任意改，且 `expire_at` 实时计算

**现状（实测）**

`cloudDays` 是 `PATCH` 的可写字段，且 `expire_at` 是**按当前 `cloudDays` 实时算**的。

```bash
# 改前：同一批卡 expire_at = 2026-10-31
curl -X PATCH ".../client/v1/devices/eval-2729-probe" \
  -H "Authorization: Bearer <clientToken>" -d '{"cloudDays":3650}'
# 改后再读：expire_at 立刻变成 2036-10-21
```

**影响**：存储是按「空间×时长」卖的，客户端把天数改成 3650 就等于**永久免费**。付费墙形同虚设。

**修复规格**

- `cloudDays` **移出客户端可写白名单**（`PATCH` 里出现该字段直接忽略或 `40001`）
- `expire_at` 在**记录创建时落库为确定值**（`create_time + 当时生效的套餐天数`），**不再实时计算**
- 套餐变更只由**服务端订阅/计费系统**写，走内部接口，不暴露公网
- 客户端读到的 `cloudDays` / `expire_at` 一律**只读**

> 验收用例：`PATCH cloudDays=3650` 应被拒绝或忽略；已存在记录的 `expire_at` 在任何写操作后保持不变。

### 4.3 🔴 `/client/v1/cards/today` 不去重

**现状（实测）**

同一张图连续上传 5 次（为测多语言），今日卡返回 4 条**完全相同**的卡，只是语言不同：

```
今日条数 4
  cola con hielo
  아이스 콜라
  冰可乐
  アイスコカ・コーラ
```

用户连续对同一个杯子按 5 次快门，今日卡就变成 4 张一样的。

**修复规格**

- 去重键：`normalize(name_english)` —— 小写 + 去首尾空格 + 去多余标点
- 同一去重键只保留**最新一条**（`seq` 最大）
- 去重**在 `today` 接口内做**，不改 `/cards` 列表行为（列表要保留全部历史）
- 响应追加 `dedupCount`（被折叠的条数），便于核对与排查

> 验收用例：同一物体拍 5 次，`/cards/today` 返回 1 条；`/cards` 仍返回 5 条。

### 4.4 ✅ `/v1/device/config` 缺失

已由 §2.5 补齐，不再是缺陷。

## 5. 🔵 与老云端 `nglearn` 的差异（App 迁移对照）

真机现在跑的是**老云端** `nglearn.turingapi.com`，新云端是另一套。**只改请求地址不够，整套数据层都要改。**

| 项 | 老 `nglearn`（现状） | 新 `thumbcamera-api` | App 侧影响 |
|---|---|---|---|
| 列表路径 | `GET /api/record/list` | `GET /client/v1/cards` | 改 |
| 认证 | query `key=apikey` + `deviceId` | `Authorization: Bearer clientToken` | 改 |
| 分页 | `page` / `size`（≤100） | `limit` / `cursor` | 改 |
| 响应外层 | `{"code":200,...}` | `{"code":0,...}` | 🔴 判断条件全改 |
| 记录 `id` | 数字 `315` | **UUID 字符串** | 🔴 Room 主键类型要改 |
| 名称 | `name_chinese` / `name_english` | `name_localized` / `name_localized_lang` | 改 |
| 第三语言 | ❌ 无（`lang` 参数被忽略） | ✅ 有 | 能力差异 |
| 今日卡 | 无（客户端按日期筛） | `/cards/today` | 新增 |
| 收藏 | 纯本地 | 云端 `favorited` + PUT | 改 |
| 详情 | `/api/record/detail?id=` | `/client/v1/cards/{id}` | 改 |
| 存储天数 | 无此概念 | `cloudDays` / `expire_at` | 新增 |

> 🔴 关键：老云端 `lang` 参数**被完全忽略**。实测带上 `&lang=ko` 与不带，响应逐字节相同，字段只有 `name_chinese` + `name_english`。
> 所以**在老链路上，App 改任何语言都不会让卡片变韩语**——语言能力只存在于新云端。

## 6. 自测脚本

```bash
B=https://thumbcamera-api.turingapi.com
BOOT=<bootstrapToken>
CLI=<clientToken>
DK=<deviceKey>
D=cam-001

# 1) 建设备（lang=zh）
curl -sS -X POST "$B/v1/devices" -H "Authorization: Bearer $BOOT" \
  -H 'Content-Type: application/json' \
  -d "{\"deviceId\":\"$D\",\"deviceKey\":\"$DK\",\"lang\":\"zh\"}"

# 2) 设备拉配置（应 corrected=false）
curl -sS -X POST "$B/v1/device/config" -H "Authorization: Bearer $DK" -H "Device-Id: $D" \
  -H 'Content-Type: application/json' -d '{"item_lang":"zh","ui_lang":"zh"}'

# 3) App 改韩语
curl -sS -X PATCH "$B/client/v1/devices/$D" -H "Authorization: Bearer $CLI" \
  -H 'Content-Type: application/json' -d '{"lang":"ko"}'

# 4) 设备再拉（应 corrected=true, item_lang=ko）
curl -sS -X POST "$B/v1/device/config" -H "Authorization: Bearer $DK" -H "Device-Id: $D" \
  -H 'Content-Type: application/json' -d '{"item_lang":"zh","ui_lang":"zh"}'

# 5) 越权验证（应 40301）
curl -sS "$B/client/v1/cards?deviceId=别人家的设备" -H "Authorization: Bearer $CLI"

# 6) 计费验证（应被拒）
curl -sS -X PATCH "$B/client/v1/devices/$D" -H "Authorization: Bearer $CLI" \
  -H 'Content-Type: application/json' -d '{"cloudDays":3650}'
```

## 7. 🔴 服务器地址可配置

### 7.1 为什么需要

- 联调期要在 prod / 测试环境之间来回切
- **新老云端并行**：老 `nglearn` 继续支撑演示，新 `thumbcamera-api` 并行开发
- 地址变更属于「唯一能把设备变成砖」的操作，必须有回滚通道

### 7.2 三层地址

| 层 | 存储 | 谁改 | 默认 |
|---|---|---|---|
| 出厂默认 | 固件常量 | 不 | `thumbcamera-api.turingapi.com` |
| 运行时 | NVS/Flash | App 经 BLE | 同出厂默认 |
| 上次成功 | NVS/Flash | 设备自己记 | 空 |

生效值 = 运行时（有则用）→ 否则出厂默认。「上次成功」**不参与选择**，只用于失败回退。

### 7.3 BLE 下发 —— 复用 `0x12 DEVICE_CONFIG`

新增两个 TLV：

| Tag | 名称 | 长度 | 值 |
|---|---|---|---|
| `0x13` | SERVER_ENDPOINT | 变长（≤96B） | 主机名，**不带 `https://`、不带尾斜杠** |
| `0x14` | SERVER_PROFILE | 1B | `0x00`=prod（默认） `0x01`=test |

示例值：`thumbcamera-api.turingapi.com`、`nglearn.turingapi.com`

> 只传主机名。scheme 和路径前缀由固件按 `profile` 自行拼接，避免把 `/v1` 或 `/api` 写进配置导致两边不兼容。

回执 `0x92`，每个 TLV 独立返回：

| 状态 | 含义 |
|---|---|
| `0x00` | 成功 |
| `0x01` | 值非法（空串 / 超长 / 含 `://` / 含空格或斜杠） |
| `0x02` | 写 Flash 失败 |

### 7.4 读取当前地址

`0x8D` 扩展新增 `0x10` ENDPOINT，返回当前生效主机名（明文）。诊断页据此显示「设备现在连的是哪台」，排查不用猜。

### 7.5 🔴 失败回退（防变砖）

本章最重要的一条。

```
设备发起请求
├─ 成功 → 把当前地址记为「上次成功」
└─ 连续 N 次失败（建议 N=5，覆盖一次完整重试周期）
     ├─ 存在「上次成功」且 ≠ 当前地址  → 回退到它，继续工作
     ├─ 不存在                        → 回退到出厂默认
     └─ 都失败                        → 保持现状，仅保持 BLE 可发现，等 App 重配
```

**硬约束：无论地址多错，BLE 配网必须始终可用。** 这是唯一救砖通道——云端连不上时，用户还能用手机通过 BLE 把地址改回来。

> ❌ 不要做「启动时连不上就无条件恢复出厂地址」：会把用户故意配的测试环境静默覆盖，联调时会出现「配了又自己变回去」的灵异现象。

### 7.6 App 侧配合

- `BuildConfig.RECORD_BASE_URL` 仍为编译期常量，**正式包不改**
- Debug 包在**诊断页**加一行「服务器」，可切 `nglearn` / `thumbcamera-api` / 自定义，确认后经 BLE `0x12` 下发
- 下发后立刻做一次连通性探测（列表第一页即可），失败则提示并保留原值

### 7.7 与语言下发的关系

两件事走同一条 BLE 通道，**顺序不能反**：

| 能力 | TLV | 作用 |
|---|---|---|
| 服务器地址 | `0x13` / `0x14` | 设备连哪台 |
| 物品 / 界面语言 | `0x10` / `0x11` | 云端按语言返回内容 |

**先发地址，再发语言。** 反过来的话，语言发给了旧服务器，切完还得重发。
